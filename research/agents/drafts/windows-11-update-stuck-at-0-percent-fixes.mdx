Windows Update stalling at `0% downloading`, `20%`, or `100% installing` is one of the most frequent support requests across corporate IT helpdesks. 

When a cumulative security patch freezes, Windows leaves its underlying Background Intelligent Transfer Service (BITS) and `SoftwareDistribution` cache in a locked state. Rebooting mid-update can result in boot loops or corrupted system files.

On our IT operations workbench, we manage hundreds of Windows 11 endpoints. Here is our 9-step escalation procedure to unfreeze Windows Update safely without losing data or damaging the OS.

---

## Why Does Windows Update Get Stuck at 0%?

1. **Corrupted `SoftwareDistribution` Cache:** Downloaded update CAB files can get corrupted mid-transit, causing the Windows Update agent to loop endlessly trying to verify signatures.
2. **BITS Service Lock:** The Background Intelligent Transfer Service hangs when network connections drop during background downloading.
3. **Third-Party Antivirus File Locking:** Endpoint security software often locks temporary update files inside `C:\Windows\SoftwareDistribution\Download`.
4. **Catroot2 Cryptographic Catalog Damage:** Windows relies on `catroot2` to verify update signatures. If catalog files corrupt, updates fail silently.

---

## 🛠️ The 4-Command Windows Update Reset (Try First)

Instead of manually stopping services through `services.msc`, run this automated reset script in an Administrative PowerShell terminal:

```powershell
# Stop Windows Update Services
Stop-Service -Name wuauserv -Force
Stop-Service -Name bits -Force
Stop-Service -Name cryptsvc -Force
Stop-Service -Name msiserver -Force

# Rename SoftwareDistribution and Catroot2 folders
Rename-Item -Path "C:\Windows\SoftwareDistribution" -NewName "SoftwareDistribution.old" -Force
Rename-Item -Path "C:\Windows\System32\catroot2" -NewName "catroot2.old" -Force

# Restart Services
Start-Service -Name wuauserv
Start-Service -Name bits
Start-Service -Name cryptsvc
Start-Service -Name msiserver
```

After executing these commands, open **Settings > Windows Update** and click **Check for updates**. Windows will generate fresh cache folders and restart the download from 0%.

---

## 🛠️ Step 2: Clear BITS Queue

If BITS is holding job locks in the background, clear its queue directly:

```cmd
:: Administrative Command Prompt
bitsadmin /reset /allusers
```

---

## 🛠️ Step 3: Repair Windows Servicing Stack (DISM & SFC)

If updates freeze during the installation phase (e.g., stuck at 35% or 100%), core servicing stack binaries may be damaged:

```cmd
DISM.exe /Online /Cleanup-Image /RestoreHealth
sfc /scannow
```

Restart your computer once both commands complete with `100%` success.
