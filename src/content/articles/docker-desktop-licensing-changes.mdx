## 3. Resolving the 3 Common Migration Hurdles

**Migrating to daemon-less rootless containers introduces major security advantages, but breaks assumptions around privileged port binding, VPN routing, and file permissions.**

### Hurdle 1: Privileged Port Binding Below 1024

**Rootless containers cannot bind to ports 80 or 443 by default on Linux or WSL2.** If a developer runs a local Nginx reverse proxy targeting port 80, the container crashes instantly with `bind: permission denied`.

**Our Production Fix:** Adjust host kernel parameters to allow unprivileged bindings starting at port 80:

```bash
# Temporarily lower the unprivileged port threshold
sudo sysctl -w net.ipv4.ip_unprivileged_port_start=80

# Persist across reboots in /etc/sysctl.d/99-podman-ports.conf
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/99-podman-ports.conf
sudo sysctl --system
```

### Hurdle 2: Rootless Volume Permissions and Ownership Mismatches

**Inside a rootless container, root (UID 0) maps to the host developer UID, causing external mount write failures when container initialization scripts call `chown`.**

**Our Production Fix:** Always launch containers using the `--userns=keep-id` flag, which maps your active host user and group directly into the container namespace, and append `:Z` for SELinux relabeling:

```bash
# Correct enterprise Podman invocation with host UID parity
podman run -d \
  --name dev-api-service \
  --userns=keep-id \
  -p 3000:3000 \
  -v $(pwd)/src:/app/src:Z \
  -v $(pwd)/node_modules:/app/node_modules:Z \
  node:20-alpine npm run dev
```

### Hurdle 3: Corporate VPN & DNS Blackholing

**Cisco AnyConnect and GlobalProtect VPN clients alter host routing tables, frequently cutting off Podman's default `slirp4netns` network stack.**

**Our Production Fix:** Configure the Podman virtual machine to forward DNS requests directly to host loopback resolvers:

```powershell
# Windows 11 PowerShell: Configure Podman Machine with host resolver forwarder
podman machine stop
podman machine set --rootful=false
wsl -d podman-machine-default -u root sh -c "echo 'nameserver 1.1.1.1' > /etc/resolv.conf"
podman machine start
```

## 4. Production Blueprints: Systemd Quadlets & GitLab CI

**Eliminate brittle startup scripts by running local background services as native systemd units with Quadlets.**

### Production Systemd Quadlet: Developer PostgreSQL 16 Stack

Instead of running docker-compose commands that fail to restart after workstation sleep cycles, save this file to `~/.config/containers/systemd/dev-postgres.container`:

```ini
# ~/.config/containers/systemd/dev-postgres.container
[Unit]
Description=Developer Local PostgreSQL 16 Service
After=network-online.target

[Container]
Image=docker.io/library/postgres:16-alpine
ContainerName=postgres-local
Environment=POSTGRES_USER=app_dev
Environment=POSTGRES_PASSWORD=local_secret_pass
Environment=POSTGRES_DB=dev_analytics
PublishPort=5432:5432
Volume=postgres_data:/var/lib/postgresql/data:Z

[Service]
Restart=always
TimeoutStartSec=60

[Install]
WantedBy=default.target
```

Enable and start the service with standard user-level systemctl commands:

```bash
# Reload systemd generator and activate local container service
systemctl --user daemon-reload
systemctl --user enable --now dev-postgres
systemctl --user status dev-postgres
```

### CI/CD Runner Configuration: Daemon-less Podman Socket

To eliminate Docker-in-Docker (`dind`) security risks and commercial licensing requirements in automated CI pipelines, mount the rootless Podman Unix socket directly:

```yaml
# .gitlab-ci.yml - Daemon-less OCI Image Build Pipeline
stages:
  - build

variables:
  DOCKER_HOST: "unix:///run/user/1000/podman/podman.sock"

build_container_image:
  stage: build
  image: quay.io/podman/stable:latest
  script:
    - podman info
    - podman build -t registry.company.internal/services/core-api:latest -f Dockerfile .
    - podman login -u "$CI_REGISTRY_USER" -p "$CI_REGISTRY_PASSWORD" registry.company.internal
    - podman push registry.company.internal/services/core-api:latest
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
```
