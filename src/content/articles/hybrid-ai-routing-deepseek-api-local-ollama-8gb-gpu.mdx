If you have tried building an AI-assisted engineering workflow this year, you have likely hit the classic developer dilemma:

1. **Cloud APIs (Frontier Reasoning):** You get state-of-the-art multi-file code synthesis and massive context windows, but every query incurs per-token billing, latency overhead, and data privacy concerns when sending raw infrastructure logs or internal credentials.
2. **Local AI (Ollama / On-Premises):** You get absolute privacy, zero API costs, and sub-50ms token latency on your consumer GPU, but running full 671B parameter models locally is physically impossible on consumer 8GB or 16GB VRAM graphics cards.

On our dev workbench, our team refused to compromise between privacy and frontier intelligence. We engineered a **lightweight Hybrid AI Routing Gateway** that splits queries dynamically: sensitive sysadmin logs and low-latency autocomplete route to **local Ollama (DeepSeek-R1-Distill-8B / Qwen2.5-Coder)**, while heavy architectural refactors route to the **cloud DeepSeek API**.

Here is our production routing architecture, decision heuristic code, and benchmark telemetry.

## ⚡ The Dynamic Routing Decision Engine (Python)

Below is the core routing middleware we run in our local Docker environment. It evaluates payload sensitivity and task complexity before choosing the inference provider:

```python
import re
import os
import requests

# Endpoints
OLLAMA_URL = "http://localhost:11434/api/generate"
DEEPSEEK_API_URL = "https://api.deepseek.com/v1/chat/completions"
DEEPSEEK_API_KEY = os.getenv("DEEPSEEK_API_KEY")

# DLP Patterns: Private IPs, API Keys, SSH Keys, Windows Event Logs
SENSITIVE_PATTERNS = [
    r"(?:10\.\d{1,3}|192\.168\.\d{1,3}|172\.(?:1[6-9]|2\d|3[01]))\.\d{1,3}",
    r"(?:AKIA|ASIA)[A-Z0-9]{16}",
    r"-----BEGIN (?:RSA|OPENSSH) PRIVATE KEY-----",
    r"sk-[a-zA-Z0-9]{32,}",
    r"EventID:\s*\d{3,5}"
]

def contains_sensitive_data(text: str) -> bool:
    """Detects internal infrastructure telemetry or secrets."""
    for pattern in SENSITIVE_PATTERNS:
        if re.search(pattern, text):
            return True
    return False

def route_ai_query(prompt: str, system_prompt: str = "") -> dict:
    """Routes query to Local Ollama or Cloud DeepSeek based on DLP & complexity."""
    
    is_sensitive = contains_sensitive_data(prompt) or contains_sensitive_data(system_prompt)
    is_short_snippet = len(prompt.split()) < 120
    
    # Policy: Always keep sensitive data on-premises
    if is_sensitive or is_short_snippet:
        print("🔒 Routing to Local Ollama (DeepSeek-R1-Distill-8B)...")
        payload = {
            "model": "deepseek-r1:8b",
            "prompt": f"{system_prompt}\n\n{prompt}",
            "stream": False,
            "options": {"num_ctx": 4096, "temperature": 0.2}
        }
        try:
            res = requests.post(OLLAMA_URL, json=payload, timeout=30)
            return {"provider": "ollama-local", "response": res.json().get("response")}
        except requests.exceptions.RequestException:
            print("⚠️ Local Ollama failed, falling back to secure cloud with redaction...")

    # Route complex, non-sensitive architectural tasks to Cloud DeepSeek API
    print("☁️ Routing to Cloud DeepSeek API (Frontier Reasoning)...")
    headers = {
        "Authorization": f"Bearer {DEEPSEEK_API_KEY}",
        "Content-Type": "application/json"
    }
    cloud_payload = {
        "model": "deepseek-reasoner",
        "messages": [
            {"role": "system", "content": system_prompt or "You are an expert systems architect."},
            {"role": "user", "content": prompt}
        ],
        "temperature": 0.3
    }
    
    response = requests.post(DEEPSEEK_API_URL, json=cloud_payload, headers=headers, timeout=60)
    data = response.json()
    return {"provider": "deepseek-cloud", "response": data["choices"][0]["message"]["content"]}
```

## 🛠️ Step-by-Step Setup Guide

### 1. Configure Local Ollama with Model Offloading
To ensure Ollama does not monopolize all VRAM when gaming or running local rendering jobs:

```bash
# Pull the optimized 8B reasoning distill model
ollama pull deepseek-r1:8b

# Pull the dedicated high-speed coding model
ollama pull qwen2.5-coder:7b
```

### 2. Set Environment Variables
Create a local `.env` file on your developer workstation:

```bash
DEEPSEEK_API_KEY="your-deepseek-api-key-here"
OLLAMA_HOST="http://localhost:11434"
```

### 3. Connect Your IDE (VS Code / Cursor / Continue.dev)
Configure your local IDE extension (such as Continue.dev) to point tab autocomplete to your local Ollama port (`11434`), and point the primary chat window to your hybrid proxy endpoint.
