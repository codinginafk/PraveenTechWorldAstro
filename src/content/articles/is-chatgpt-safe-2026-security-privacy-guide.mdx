## 🔒 3 Critical Security Risks in ChatGPT (And How to Mitigate Them)

### 1. Model Training Ingestion (Free & Plus Tiers)
When employees use personal Free accounts, raw prompts can be used by OpenAI to train future public models.
- **Remediation:** If using consumer tiers, navigate to **Settings $\rightarrow$ Data Controls** and toggle off **Improve the model for everyone**.

### 2. Accidental Credential & Token Leaks
Developers frequently paste configuration blocks containing database connection strings, JWT signing keys, or AWS access tokens into chat prompts.
- **Remediation:** Enforce network-level Data Loss Prevention (DLP) proxies to sanitize API keys before transmission.

### 3. Prompt Injection & Indirect Jailbreaks
When feeding untrusted web content or un-sanitized PDF documents to ChatGPT, malicious prompt injections can trick the model into executing unauthorized tool calls.
- **Remediation:** Restrict autonomous agent tool permissions and sandbox code interpreters in isolated Docker containers.

## 🛡️ Zero Data Retention (ZDR) for OpenAI API

For enterprise applications requiring strict compliance (such as healthcare and legal services), organizations can request **Zero Data Retention (ZDR)** on the OpenAI Platform API:

1. Under ZDR agreements, prompt payloads and completions are processed strictly in volatile RAM.
2. Data is never written to OpenAI persistent disk storage, even for abuse monitoring.
3. Organizations must maintain their own internal audit logging to satisfy legal discovery requirements.
