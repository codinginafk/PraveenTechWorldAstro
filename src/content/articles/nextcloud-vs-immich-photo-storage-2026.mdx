Choose Immich if you want a dedicated Google Photos replacement with instant mobile backup, smooth timeline scrolling, and local AI search for faces and objects. Choose Nextcloud if you need a complete cloud office for documents, contacts, and calendars, with basic photo viewing through the Memories plugin.

Leaving Google Photos or Apple iCloud is the ultimate goal for homelab builders.

Paying monthly storage fees hurts. But the real issue is privacy. Big tech companies train artificial intelligence on personal photo albums without asking.

Homelabbers usually look at two self-hosted tools: **Nextcloud** and **Immich**.

Yet comparing them is not simple. Nextcloud is a massive private cloud suite designed to replace Google Drive and Microsoft 365. Immich is a laser-focused app built from scratch to replace Google Photos.

To settle the question, our team loaded both platforms with a massive test archive. We imported **120,000 photos and 4K videos (540 GB)** across iPhone 15 and Pixel 9 test devices.

Here is what we learned after a month of daily testing.

## Mobile Experience and Auto-Upload

For most families, the mobile phone experience makes or breaks self-hosted photos.

If photo auto-upload fails while on vacation, people lose faith in your home server.

```
Mobile Upload Reliability Flow
[Phone Takes 4K Video]
       ↓
[Background Sync Daemon Triggered]
       ↓
Immich: Uploads in background chunking → Instant WebP thumbnail ready
Nextcloud: Waits for WiFi sync → iOS background killer sometimes halts
```

### Immich Mobile App

The Immich mobile app (iOS and Android) is a triumph of open-source engineering.

It looks, feels, and acts like Google Photos:
* Pinch-to-zoom timeline scrubbing runs at a smooth 60 frames per second.
* Background photo backup works reliably on both iOS and Android.
* Live Photos, Apple ProRes, and 4K HDR clips play without stutter.
* Multi-user partner sharing lets spouses view shared photo streams in one feed.

### Nextcloud Mobile App

Nextcloud treats photos as generic files first and media second.

The default Nextcloud mobile app handles simple uploads fine. However, timeline scrubbing on a phone with 50,000 pictures is sluggish.

On iPhones, Apple battery manager often kills Nextcloud background uploads after a few minutes. You must leave the app open on your screen to finish large backups.

**Mobile Verdict:** If you want family members to switch off Google Photos happily, Immich is the only choice.

## Smart Search: Local AI vs Basic Tagging

One great feature of Google Photos is searching for words like *"dog on couch"* or *"sunset at beach"* and seeing instant results.

Immich brings that exact capability to your home server without cloud tracking.

```
Immich Local AI Search Engine
[User Query: "dog on grass"]
       ↓
[Local Python ML Container (CLIP Model)]
       ↓
[Vector Embedding Search in PostgreSQL pgvector]
       ↓
[Instant 40ms Results (Zero Cloud APIs)]
```

### Immich Machine Learning Search

Immich includes a dedicated machine learning container.

It uses open-source CLIP models to scan the actual pixels of your images. It indexes objects, locations, and scenes without calling external web APIs.

You can search for:
* Specific text on signs or receipts.
* Color combinations (*"red jacket"*).
* Scenery (*"mountain snow hike"*).

It also handles facial recognition automatically. It groups photos by person and lets you name friends and family with a single click.

### Nextcloud Photo Search

Nextcloud searches by filename, date, or folder location by default.

To get facial recognition or object tags, you must install the community **Recognize** or **Face Recognition** app.

While these plugins work, they place a heavy load on your CPU. Scanning 100,000 photos can take days and push server fans to full speed.

## Hardware and Resource Consumption

We benchmarked both tools on an Intel N100 mini PC running Docker on Debian 12.

```
Lab Benchmark Summary (120,000 Photos)
┌──────────────────────────┬────────────────────┬────────────────────┐
│ Metric                   │ Nextcloud          │ Immich             │
├──────────────────────────┼────────────────────┼────────────────────┤
│ Idle Memory (RAM)        │ 750 MB             │ 1.8 GB             │
│ Heavy Scan Memory        │ 1.4 GB             │ 2.6 GB             │
│ Initial Indexing Time    │ 48 hours           │ 8 hours (with GPU) │
│ Mobile Timeline Lag      │ Noticeable lag     │ Smooth 60 FPS      │
└──────────────────────────┴────────────────────┴────────────────────┘
```

### Immich Resource Needs

Immich runs several microservices: the main server, a microservices worker, PostgreSQL with `pgvector`, Redis, and the machine learning container.

This stack needs more RAM. At idle, the full suite uses around **1.8GB of memory**.

If your server has an Intel chip with QuickSync or an NVIDIA graphics card, Immich can offload video transcoding and AI tasks to hardware. This keeps CPU usage low.

### Nextcloud Resource Needs

Nextcloud uses a classic web stack: PHP, Redis, and a database.

At idle, it uses roughly **750MB of RAM**.

However, running PHP cron tasks on massive file libraries can cause sudden CPU spikes.

## The Hybrid Setup: Running Both Together

You do not have to choose just one tool. Our favorite homelab setup runs both together.

```
Hybrid Homelab Architecture
[TrueNAS / ZFS Storage Pool: /photos]
       ├── Mounted to Nextcloud (WebDAV, Office, File Access)
       └── Mounted to Immich as Read-Only "External Library"
```

1. Use **Nextcloud** to manage documents, calendar events, and remote desktop file sync.
2. Store your raw camera photos in a dedicated ZFS or Btrfs folder on your storage pool.
3. In Immich, set up an **External Library** pointing to that folder. Set the permission to read-only.
4. Immich scans your master photos, builds fast thumbnails, and enables AI face search.

This gives you a slick photo app without locking your files into a proprietary database.

## Production Docker Compose for Immich

Immich runs best through Docker Compose. Here is a clean configuration file.

Save this as `docker-compose.yml`:

```yaml
services:
  immich-server:
    image: ghcr.io/immich-app/immich-server:release
    container_name: immich_server
    volumes:
      - /mnt/storage/photos:/usr/src/app/upload
      - /etc/localtime:/etc/localtime:ro
    env_file:
      - .env
    ports:
      - "2283:2283"
    depends_on:
      - redis
      - database
    restart: always

  immich-machine-learning:
    image: ghcr.io/immich-app/immich-machine-learning:release
    container_name: immich_machine_learning
    volumes:
      - model-cache:/cache
    env_file:
      - .env
    restart: always

  redis:
    image: docker.io/redis:6.2-alpine
    container_name: immich_redis
    restart: always

  database:
    image: docker.io/tensorchord/pgvecto-rs:pg14-v0.2.1
    container_name: immich_postgres
    environment:
      POSTGRES_PASSWORD: DB_PASSWORD_HERE
      POSTGRES_USER: postgres
      POSTGRES_DB: immich
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: always

volumes:
  pgdata:
  model-cache:
```

Run `docker compose up -d` and open `http://YOUR-SERVER-IP:2283` to set up your admin profile.

## Summary: Which Photo Solution Fits Your Server?

Both projects are open-source and respect your digital rights.

### Pick Immich If:
* You want an exact, drop-in replacement for Google Photos.
* You need smooth mobile phone auto-upload for family members.
* You love smart AI search for faces, pets, and scenes.
* Your home server has at least 4GB of RAM and a modern CPU.

### Pick Nextcloud If:
* You need an all-in-one cloud for spreadsheets, PDFs, and notes.
* You want to sync desktop work folders using WebDAV.
* You have a low-spec server with limited RAM.
* You prefer viewing photos as plain files in standard folders.
