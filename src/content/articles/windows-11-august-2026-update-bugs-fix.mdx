## 🛠️ Issue 1: Windows Update Stalls or Fails with Error `0x800f0983`

### The Root Cause
Error `0x800f0983` occurs when the Windows Update agent downloads incomplete or cryptographically mismatched delta payloads into the local cache. When the Component-Based Servicing (CBS) engine attempts to verify hash manifests during the staging phase, it halts the installation.

```
+-------------------------------------------------------------+
| Windows Update Agent -> Partial / Corrupted Delta Download  |
+-------------------------------------------------------------+
                              |
                     Hash Verification Fail
                              |
                              v
+-------------------------------------------------------------+
| Staging Halts at 96% -> Error 0x800f0983 -> Auto Rollback   |
+-------------------------------------------------------------+
```

### The Fix: Purge the SoftwareDistribution & Catroot2 Cache
Run the following commands in **PowerShell as Administrator**:

```powershell
# 1. Stop Update and Cryptographic Services
Stop-Service -Name wuauserv -Force
Stop-Service -Name bits -Force
Stop-Service -Name cryptsvc -Force

# 2. Purge SoftwareDistribution and Catroot2
Remove-Item -Path "C:\Windows\SoftwareDistribution\Download\*" -Recurse -Force
Rename-Item -Path "C:\Windows\System32\catroot2" -NewName "catroot2.old" -Force

# 3. Restart Services
Start-Service -Name cryptsvc
Start-Service -Name bits
Start-Service -Name wuauserv

# 4. Force Update Detection
(New-Object -ComObject Microsoft.Update.AutoUpdate).DetectNow()
```

## 🔧 Issue 2: Error `0x800f0915` (CBS Component Store Corruption)

### The Root Cause
Error `0x800f0915` indicates that the underlying Component-Based Servicing repository has missing component payloads or the EFI System Partition (ESP) lacks sufficient staging room (under 100 MB free) to commit bootloader binaries.

### The Fix: Sequential DISM Image Restoration & SFC Repair
Execute these commands in sequence (**Run as Administrator**):

```powershell
# 1. Check Component Store Health
dism.exe /Online /Cleanup-Image /ScanHealth

# 2. Repair Component Store from Windows Update Online Repository
dism.exe /Online /Cleanup-Image /RestoreHealth

# 3. Verify System File Integrity
sfc.exe /scannow
```

> 💡 **Bench Tip:** Always let DISM complete to 100% before running `sfc /scannow`. If DISM fails to fetch source files online, mount a clean Windows 11 ISO and point DISM to the `install.wim` file:
> `dism /Online /Cleanup-Image /RestoreHealth /Source:WIM:D:\sources\install.wim:1 /LimitAccess`

## 🎮 Issue 3: Game Micro-Stuttering & Black Screens on Nvidia GPUs

### The Root Cause
Following update KB5121003, hypervisor paging protections interact aggressively with the Windows Display Driver Model (WDDM 3.2). Workstations running older graphics drivers or aggressive hardware-accelerated GPU scheduling (HAGS) settings experience PCIe bus paging deadlocks (Event ID 153), resulting in 2-second screen freezes or sudden black displays during full-screen 3D rendering.

### The Fix: Clean Safe Mode DDU & Registry TDR Extension

```
[ Step 1: Boot into Windows Safe Mode ]
                 |
                 v
[ Step 2: Run Display Driver Uninstaller (DDU) -> Clean and Restart ]
                 |
                 v
[ Step 3: Install Latest Game Ready Driver (Clean Install Checked) ]
                 |
                 v
[ Step 4: Apply TdrDelay Registry Key to Prevent Watchdog Panic ]
```

#### Apply TdrDelay Extension (Elevated PowerShell)

```powershell
# Extend Timeout Detection and Recovery (TDR) Watchdog to 8 Seconds
$registryPath = "HKLM:\SYSTEM\CurrentControlSet\Control\GraphicsDrivers"
Set-ItemProperty -Path $registryPath -Name "TdrDelay" -Value 8 -Type DWord
Set-ItemProperty -Path $registryPath -Name "TdrDdiDelay" -Value 8 -Type DWord
```

In your motherboard BIOS, also lock the **PCIe Link Speed** from `Auto` to `Gen 4` or `Gen 5` to prevent link-state power management (ASPM) latency drops.

## 🛡️ Issue 4: Fake "Virus & Threat Protection Is Turned Off" Notification

### The Root Cause
After applying the August servicing stack update, the Windows Security Center service (`wscsvc`) occasionally loses synchronization with the Windows Management Instrumentation (WMI) security namespace repository. Although Microsoft Defender Antivirus is running actively in the background, the Action Center displays a red warning banner claiming virus protection is disabled.

### The Fix: Rebuild the WMI Repository
Open **Command Prompt as Administrator** and execute:

```cmd
winmgmt /verifyrepository
winmgmt /resetrepository
net stop wscsvc && net start wscsvc
```

Restart your computer. The Windows Security dashboard will immediately reflect the active Defender status in green.

## ✉️ Issue 5: Outlook Classic & MAPI Applications Crash on Startup

### The Root Cause
Cumulative update KB5121003 introduced strict memory boundary checks that conflict with third-party MAPI search indexing add-ins and corrupted Outlook cache (`.ost`) profile headers.

### The Fix: Safe Mode Add-in Isolation & OST Rebuild

1. Press `Win + R`, type `outlook.exe /safe`, and press **Enter**.
2. If Outlook opens cleanly, go to **File > Options > Add-ins > COM Add-ins > Go**, and disable all third-party search and security plugins.
3. If crashes persist, rename the local cached data file to force a clean server resync:
   ```powershell
   # Rename existing OST file (Outlook must be closed)
   Rename-Item "$env:LOCALAPPDATA\Microsoft\Outlook\*.ost" -NewName "backup.ost" -Force
   ```
4. Relaunch Outlook to regenerate the offline store.
