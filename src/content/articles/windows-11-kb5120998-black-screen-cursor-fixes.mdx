**To fix the Windows 11 KB5120998 black desktop and cursor reset glitch, open PowerShell as Administrator and run `wusa /uninstall /kb:5120998 /quiet /norestart`. If you cannot uninstall the cumulative update, delete the corrupted `%AppData%\Microsoft\Windows\Themes\TranscodedWallpaper` cache file, set your cursor scheme back to Windows Default, and restart `explorer.exe` via Task Manager.**

On our workbench, when our engineering workstations and testbed laptops pulled the cumulative update **KB5120998** (Build 26100.9278), our team immediately ran into a bizarre desktop breakdown: multi-monitor custom wallpapers were wiped and replaced with solid charcoal-black voids, high-DPI custom mouse cursors reverted to miniature default arrows on reboot, and on ARM64 Snapdragon dev units, Outlook and Teams crashed with access violation `0xc0000005`.

If you just installed this update and your desktop looks broken, do not reformat your machine or reinstall Windows. This is a documented servicing regression in the Desktop Window Manager (`dwm.exe`) shell pipeline.

Here is the exact technical breakdown of why KB5120998 breaks desktop personalization, followed by our team's three verified command-line fixes.

## Method 1: The Clean Rollback via WUSA & DISM (Recommended)

**Rolling back KB5120998 via Windows Update Standalone Installer (`wusa.exe`) is the fastest way to restore stability until Microsoft issues an emergency out-of-band revision.**

If your machine is actively crashing applications or refusing to display desktop graphics, uninstalling the cumulative package takes under three minutes.

### Step 1: Execute the WUSA Uninstall Command

Open **PowerShell as Administrator** (press `Win + X`, then press `A`) and run:

```powershell
# Uninstall Windows 11 Cumulative Update KB5120998
wusa /uninstall /kb:5120998 /quiet /norestart
```

The `/quiet` switch suppresses interactive dialogs, and `/norestart` gives you time to save open work. Wait 60 to 90 seconds while the Component-Based Servicing (`CBS`) engine unstages the update binaries, then reboot your system:

```powershell
Restart-Computer -Force
```

### Step 2: Fallback via DISM Package Servicing

If Windows Update returns the error *"Update for Microsoft Windows (KB5120998) is required by your computer and cannot be uninstalled"*, you can bypass the block using DISM directly:

```powershell
# 1. Identify the full Package Identity string
dism /online /get-packages /format:table | findstr "5120998"

# 2. Remove the package directly from the servicing store
# Replace the package name below with the exact string returned above:
dism /online /remove-package /PackageName:Package_for_RollupFix~31bf3856ad364e35~amd64~~26100.9278.1.0 /quiet /norestart
```

Once completed, reboot. To prevent Windows Update from reinstalling KB5120998 overnight, open **Settings > Windows Update** and select **Pause for 1 week**.

## Method 2: Rebuild the Corrupted TranscodedWallpaper Cache (No Rollback)

**If your corporate IT policy prevents update rollbacks, you can fix the solid black desktop by flushing Windows' corrupted personalization cache.**

When KB5120998 installs, it leaves a zero-byte or corrupt header in the binary wallpaper cache file. Windows cannot parse the file, so it defaults to a pure black RGB canvas.

Open PowerShell as Administrator and run our team's automated theme cache purge sequence:

```powershell
# ====================================================================
# PraveenTechWorld - Windows 11 Wallpaper Cache Rebuilder
# Purges corrupted TranscodedWallpaper and restarts Explorer
# ====================================================================

Write-Host "Stopping Windows Explorer shell..." -ForegroundColor Cyan
Stop-Process -Name explorer -Force

# Define Theme Cache Paths
$themesPath = "$env:APPDATA\Microsoft\Windows\Themes"
$transcodedFile = Join-Path $themesPath "TranscodedWallpaper"
$cachedFilesDir = Join-Path $themesPath "CachedFiles"

# Delete corrupted cache binaries
if (Test-Path $transcodedFile) {
    Remove-Item $transcodedFile -Force
    Write-Host "Purged corrupted TranscodedWallpaper binary." -ForegroundColor Green
}

if (Test-Path $cachedFilesDir) {
    Remove-Item "$cachedFilesDir\*" -Recurse -Force
    Write-Host "Cleared CachedFiles theme directory." -ForegroundColor Green
}

# Restart Explorer Shell
Write-Host "Restarting Windows Explorer..." -ForegroundColor Cyan
Start-Process explorer.exe

Write-Host "Personalization cache rebuilt successfully! Re-select your wallpaper in Settings." -ForegroundColor Green
```

After running the script, open **Settings > Personalization > Background**, select any wallpaper image, and Windows will generate a fresh, uncorrupted cache.

## Method 3: Fix Custom Mouse Cursors Resetting on Reboot

**KB5120998 introduces an access-control desynchronization in User32 that drops custom `.cur` and `.ani` pointer schemes upon user logout.**

If your mouse cursor shrinks to a microscopic default pointer or resets to default every morning, apply these two system registry adjustments:

### Step 1: Force User32 Scheme Refresh

Open PowerShell and re-register the active cursor scheme under your current user profile:

```powershell
# Re-apply current user cursor scheme
$cursorPath = "HKCU:\Control Panel\Cursors"
Set-ItemProperty -Path $cursorPath -Name "Scheme Source" -Value 1 -Type DWord
Set-ItemProperty -Path $cursorPath -Name "Current" -Value "Windows Default" -Type String

# Refresh system pointer parameters via User32 API
Add-Type -TypeDefinition @"
using System;
using System.Runtime.InteropServices;
public class User32 {
    [DllImport("user32.dll", SetLastError = true)]
    public static extern bool SystemParametersInfo(uint uiAction, uint uiParam, IntPtr pvParam, uint fWinIni);
}
"@
[User32]::SystemParametersInfo(0x0057, 0, [IntPtr]::Zero, 3) # SPI_SETCURSORS
```

### Step 2: Toggle Mouse Pointer Trails / Shadow

1. Press `Win + R`, type `main.cpl`, and press **Enter** to open Mouse Properties.
2. Switch to the **Pointers** tab.
3. Check the box labeled **Enable pointer shadow**.
4. Click **Apply** and **OK**.

Toggling the hardware pointer shadow forces DWM to create an independent composite surface for the pointer hardware layer, bypassing the compositing bug introduced in KB5120998.
