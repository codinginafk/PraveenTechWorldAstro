## The Root Causes: Why AI Agents Get Trapped

Autonomous agent loops rely on a continuous cycle: **Observation → Thought → Action → Observation**. When this loop breaks, it usually stems from two distinct mechanics:

### 1. Token Reinforcement & Static Error Feedback
When an LLM calls a tool and receives an error message (like `404 Not Found` or `Permission Denied`), that error string is appended directly to the conversation history. In the next iteration, the model evaluates its full prompt context. Because the token sequence of the previous action is now reinforced in memory without clear guidance on how to pivot, the model's highest-probability next token sequence is often **the exact same tool call**.

### 2. Context Window Dilution ("Lost in the Middle")
As an agent executes multiple tool calls, raw JSON payloads, terminal outputs, and stack traces accumulate rapidly. Once prompt length exceeds 16,000–32,000 tokens, the LLM suffers from attention degradation. Core system instructions (such as *"Never retry a failed tool call more than twice"*) get pushed up into early prompt positions and overridden by recent, noisy tool outputs.

## Pattern 1: Implementing Hash-Based Cycle Detection Middleware

The most effective line of defense is a lightweight **cycle detector** placed inside your agent's execution loop. Before executing any tool, hash the tool name combined with its stringified arguments. If the exact same tuple appears more than $N$ times within a rolling window, interrupt execution immediately.

Here is the exact Python middleware class our team uses in production:

```python
import hashlib
import json
from collections import deque
from typing import Dict, Any, List, Tuple

class AgentCycleDetector:
    def __init__(self, max_repeats: int = 2, history_window: int = 10):
        self.max_repeats = max_repeats
        self.history = deque(maxlen=history_window)

    def _hash_action(self, tool_name: str, tool_args: Dict[str, Any]) -> str:
        """Create a deterministic SHA-256 hash of the tool action."""
        serialized = json.dumps({"tool": tool_name, "args": tool_args}, sort_keys=True)
        return hashlib.sha256(serialized.encode('utf-8')).hexdigest()

    def check_and_record(self, tool_name: str, tool_args: Dict[str, Any]) -> Tuple[bool, int]:
        """
        Returns (is_infinite_loop, repeat_count).
        If is_infinite_loop is True, the agent must abort or switch strategies.
        """
        action_hash = self._hash_action(tool_name, tool_args)
        repeat_count = sum(1 for h in self.history if h == action_hash)
        
        self.history.append(action_hash)
        
        if repeat_count >= self.max_repeats:
            return True, repeat_count + 1
        return False, repeat_count + 1

# Example Execution Loop Guard
detector = AgentCycleDetector(max_repeats=2)

def execute_agent_step(agent_decision):
    tool_name = agent_decision["tool"]
    tool_args = agent_decision["args"]
    
    is_loop, count = detector.check_and_record(tool_name, tool_args)
    if is_loop:
        # Inject explicit system intervention instead of executing the broken tool
        return f"SYSTEM INTERVENTION: Tool '{tool_name}' with args {tool_args} has failed {count} times consecutively. Do NOT call this tool again. Pivot your strategy or ask the user for clarification."
    
    return run_tool(tool_name, tool_args)
```

## Pattern 2: Dynamic Context Truncation & Rolling Scratchpads

Rather than appending every raw tool output directly into the main message array, separate your agent's state into two layers:

1. **Immutable System & Objective Prompt:** Stays fixed at index 0.
2. **Rolling Working Scratchpad:** Summarizes past observations and truncates raw tool outputs after 3 steps.

| Context Strategy | Memory Footprint | Loop Risk | Re-rank Accuracy |
| :--- | :--- | :--- | :--- |
| **Naive Append All** | 45k+ tokens | Very High | 42% |
| **Fixed Max Message Window** | 12k tokens | Medium | 68% |
| **Scratchpad + Dynamic Truncation** | ~4k tokens | Extremely Low | 94% |

Here is how to prune tool output strings before feeding them back into context:

```python
def sanitize_tool_output(output: str, max_chars: int = 1500) -> str:
    """Truncate massive terminal logs while preserving critical error tails."""
    if len(output) <= max_chars:
        return output
        
    head = output[:600]
    tail = output[-700:]
    truncated_bytes = len(output) - (600 + 700)
    
    return f"{head}\n\n[... {truncated_bytes} characters truncated for context efficiency ...]\n\n{tail}"
```

## Pattern 3: Framework-Level Recursion Limits

If you are using established frameworks like **LangGraph** or **CrewAI**, ensure you explicitly override the default recursion limits:

### LangGraph Implementation
In LangGraph, pass `recursion_limit` directly in the execution config dictionary:

```python
from langgraph.graph import StateGraph

# Define your compiled graph
app = workflow.compile()

# Enforce strict maximum step depth
config = {"recursion_limit": 15}

try:
    result = app.invoke({"messages": [("user", "Audit code base")]}, config=config)
except Exception as e:
    print(f"Agent execution safely halted by recursion limit: {e}")
```

### CrewAI Implementation
In CrewAI, configure `max_iter` and `max_execution_time` on the Agent definition:

```python
from crewai import Agent

code_auditor = Agent(
    role='Senior DevOps Auditor',
    goal='Identify missing environment variables',
    backstory='Obsessive infrastructure reviewer',
    max_iter=10,  # Hard stop after 10 iterations
    max_execution_time=120, # Hard timeout after 2 minutes
    verbose=True
)
```

## Pattern 4: Injecting Structured System Interventions

When a tool fails or cycle detection triggers, **never return raw stack traces**. Instead, format the output as a structured `SYSTEM_INTERVENTION` instruction.

```json
{
  "status": "TOOL_EXECUTION_BLOCKED",
  "reason": "Duplicate action detected",
  "failed_tool": "query_database",
  "attempt_count": 3,
  "required_action": "Modify SQL query conditions or explain why required tables are missing."
}
```

By providing clear, structured error metadata, the LLM's next reasoning step is guided toward problem-solving rather than mindless repetition.
