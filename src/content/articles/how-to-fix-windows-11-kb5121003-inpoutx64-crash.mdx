Yes—fix KB5121003 game crashes by checking the `inpoutx64` service first. According to Microsoft, the Windows 11 24H2/25H2 issue affects 3 named games and the reversible test is setting `Start` to `4`.

That is the short answer. The longer explanation matters because this change disables the driver at startup; it does not prove that the update caused every crash, and it can stop RGB controls from working. Microsoft added the known issue on August 20, 2026 and the workaround on August 21. Its release note lists ARC Raiders, MARVEL Tōkon: Fighting Souls, and THE FINALS, plus four reported symptoms: an unresponsive game, an unexpected close, `EXCEPTION_ACCESS_VIOLATION`, or a device restart. The investigation remains open, so this guide keeps confirmed facts separate from checks that help you isolate another cause.

Microsoft added this issue to the [KB5121003 release notes](https://support.microsoft.com/en-us/servicing/os/windows-11/2026/08/kb5121003-windows-11-24h2-25h2-security-update) on August 20, 2026 and added the workaround on August 21. Microsoft names ARC Raiders, MARVEL Tōkon: Fighting Souls, and THE FINALS in its reports. It also says that the investigation is ongoing, so this page separates confirmed symptoms from reasonable troubleshooting checks.

## Is your symptom the KB5121003 inpoutx64 issue?

**The strongest match is a game problem that began after KB5121003, especially on a PC with RGB or peripheral-control software.** Microsoft’s listed symptoms are:

- the game becomes unresponsive;
- the game closes without notice;
- Windows displays `EXCEPTION_ACCESS_VIOLATION`;
- the device restarts without warning.

The timing alone does not prove that KB5121003 caused your crash. A graphics driver, anti-cheat update, damaged game files, overclock, or unrelated Windows error can look similar. Before changing the registry, write down the Windows edition and build, the game, the time of the crash, the exact error, and the RGB or hardware utilities installed on the PC.

Open **Settings > Windows Update > Update history > Quality Updates** and confirm that KB5121003 is installed. You can also check from PowerShell:

```powershell
# Confirm whether KB5121003 is installed
Get-HotFix -Id KB5121003 -ErrorAction SilentlyContinue |
  Select-Object HotFixID, InstalledOn, Description
```

If the command returns nothing, do not apply this workaround just because a game crashed. Troubleshoot the actual error instead. For general Windows update failures, use [the Windows 11 update troubleshooting guide](/blog/fix-windows-11-update-errors-2026-troubleshooting).

## Which RGB or peripheral software can install inpoutx64?

**Look for software that controls lighting, fan curves, sensors, or other low-level peripheral functions.** The driver name may appear in a service entry even when the application uses a different brand name. Microsoft does not publish a complete vendor list, so do not treat a forum list as proof that a particular product is responsible.

Run this read-only query in an elevated PowerShell window:

```powershell
# Find services whose image path or service name mentions inpout
Get-CimInstance Win32_SystemDriver |
  Where-Object { $_.PathName -match 'inpout' -or $_.Name -match 'inpout' } |
  Select-Object Name, DisplayName, State, StartMode, PathName
```

Also check **Settings > Apps > Installed apps** for RGB suites, motherboard utilities, peripheral dashboards, fan controllers, and hardware-monitoring tools. Do not uninstall a security, chipset, or storage driver just because its name looks unfamiliar. Capture the vendor and version first, then check whether an updated release is available.

## How do you back up the registry before changing Start?

**Back up the service key before editing it, because the workaround changes how a kernel driver starts.** Microsoft’s [registry backup guidance](https://support.microsoft.com/en-us/windows/how-to-back-up-and-restore-the-registry-in-windows-855140ad-7a9a-41d0-8079-3b4b2a9f8f34) explains the supported process.

1. Press **Windows key + R**, type `regedit`, and press **Enter**.
2. Approve the administrator prompt.
3. In Registry Editor, select **Computer** at the top of the tree.
4. Choose **File > Export**, select **All** under Export range, and save the backup to a location you can find from another device.
5. To create a smaller backup as well, navigate to `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\inpoutx64`, right-click the key, choose **Export**, and save it with a date in the filename.

If the `inpoutx64` service key does not exist, stop. Do not create it and do not disable a similarly named service without evidence that it belongs to the affected RGB or peripheral component.

## How do you apply Microsoft’s inpoutx64 workaround?

**Set the driver’s `Start` value to 4, then restart Windows.** Microsoft documents this exact workaround for the KB5121003 known issue.

1. In Registry Editor, open `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\inpoutx64`.
2. In the right pane, double-click the value named **Start**.
3. Enter `4` in **Value data**. Leave **Base** set to hexadecimal unless the existing value uses another base.
4. Select **OK**, close Registry Editor, and restart the PC.
5. Launch the same game and reproduce the same menu or match where it previously failed.

Changing `Start` to 4 disables the service at startup; it does not remove the file or uninstall the RGB application. This makes the test reversible. Microsoft warns that disabling the driver can break RGB lighting or the software that controls it. If the game works but lighting stops, that tradeoff confirms a useful correlation, not a permanent repair.

Do not run `sc delete`, delete files from `System32\drivers`, or use `pnputil` unless the hardware vendor’s instructions identify the correct package. Removing a driver file while its application still expects it can create a second startup error.

## What does changing Start to 4 actually test?

**It tests whether the named service is involved without removing the driver package.** Windows reads the service’s `Start` value during boot. In this Microsoft workaround, `4` prevents the `inpoutx64` service from starting automatically. It does not uninstall KB5121003, erase the `.sys` file, or remove the RGB application. That distinction makes the result easier to undo and explain to a vendor.

Use a before-and-after note rather than relying on memory. Record the original value, the game version, the RGB utility version, and the exact menu or match that produced the failure. Then restart once, reproduce the same action, and write down whether the symptom changed. A single successful launch is useful evidence, but it is not a controlled benchmark; test the same scenario at least twice before treating the result as a correlation.

You can capture the service state before and after the test from an elevated PowerShell window:

```powershell
# Check the service configuration before or after the registry test
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\inpoutx64' -Name Start -ErrorAction SilentlyContinue |
  Select-Object PSPath, Start
```

If the key is missing, the service has a different name, or the command returns an access error, stop and use the hardware vendor’s documentation. Do not guess at a similarly named service. After the restart, check **Event Viewer > Windows Logs > System** and **Application** for the same timestamp. A new graphics-driver, anti-cheat, or storage error points to a different troubleshooting path, even if the crash happened after the Windows update.

This test also explains why the RGB side effect matters. If the game stops crashing while lighting or fan-control features disappear, you have a reproducible lead for an RGB utility update. If the game still fails and the service state changed to `4`, restore the original value and continue with the graphics-driver, game-file, or anti-cheat checks instead of leaving a security-sensitive component disabled indefinitely.

## How do you restore RGB features after the test?

**Restore the original `Start` value from your registry backup only after you have closed the game and accepted the risk.** Microsoft says you can restore the key if the workaround causes unintended RGB or peripheral behavior.

1. Open Registry Editor as Administrator.
2. Navigate to `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\inpoutx64`.
3. Double-click **Start** and enter the value you recorded before the test.
4. Restart Windows and verify that the RGB or peripheral software loads.

If the old value is unknown, restore the exported registry key or reinstall the latest vendor package from the manufacturer; do not delete the service key just to guess a numeric start mode. If the driver returns with the same game failure, report the result through Feedback Hub.

## What should you update besides the registry?

**Update the game, RGB utility, motherboard firmware, and graphics driver from their official sources, but change one variable at a time.** A vendor may publish a package that avoids the issue without disabling the entire lighting feature. Record each version before and after the update.

- Update Windows Security intelligence and the game through their normal supported channels.
- Install a current graphics driver from NVIDIA, AMD, or Intel if the crash also appears in unrelated games.
- Update the motherboard or peripheral utility from its manufacturer; avoid third-party driver-pack sites.
- Disable overlays and overclocks for one comparison run.
- Verify game files through the launcher if the crash is limited to one title.

If the crash continues with `inpoutx64` disabled, the KB5121003 issue may not be the cause. ## Should you uninstall KB5121003?

**Use rollback only as a controlled compatibility test or an approved enterprise change; it is not the first-line workaround documented by Microsoft.** KB5121003 contains security fixes and Secure Boot certificate deployment changes. Removing it can restore a game while leaving the PC without current protections, and Windows Update may reinstall it later.

If you must test a rollback, first back up important files and record the current OS build. Open **Settings > Windows Update > Update history > Uninstall updates**, select the KB, and follow the prompts. On managed devices, ask the administrator for the approved change window. Do not use a random `wusa` command copied from a forum without confirming the package and architecture.

After the test, reinstall the update when Microsoft publishes a fix or your administrator approves it. Keep the RGB driver disabled or updated if that is the component causing the conflict. For a separate update reboot loop, see [the Windows update and Secure Boot recovery guide](/blog/why-pc-reboots-3x-after-windows-update-secure-boot-cert-fix).

## How do you report a remaining KB5121003 crash?

**Send Microsoft reproducible details instead of only reporting that “the patch broke games.”** Press **Windows key + F** to open Feedback Hub. Include:

1. Windows edition, version, and OS build.
2. KB5121003 installation date.
3. Game name and exact symptom.
4. RGB or peripheral software and driver versions.
5. Whether changing `Start` to 4 changed the result.
6. Event Viewer entries or a crash report, with personal data removed.

Microsoft says its investigation is ongoing. A later release-note update may change the workaround, affected games, or recommended recovery path. Check the official KB page before repeating an old registry instruction.

## Final KB5121003 checklist

**Confirm the update, identify the RGB-related driver, back up the registry, apply the reversible `Start=4` workaround, and report or roll back only with a reason.**

- Confirm KB5121003 and the Windows 11 version.
- Match the symptom to Microsoft’s list: freeze, close, access violation, or restart.
- Identify `inpoutx64` without deleting files.
- Export the registry before editing.
- Set `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\inpoutx64\Start` to `4`.
- Restart and retest the same game scenario.
- Update the vendor utility when available.
- Restore the previous value if RGB features are more important than the temporary workaround.
- Use Feedback Hub and the official KB page for follow-up changes.

This approach preserves the security update while testing the exact component Microsoft identified. It also leaves a clean trail for deciding whether the next action is a vendor update, a restored RGB driver, a supported rollback, or a different crash investigation entirely.
