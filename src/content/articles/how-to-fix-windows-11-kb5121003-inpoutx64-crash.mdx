Following the release of Microsoft's **August 11, 2026 mandatory cumulative update (KB5121003)** for Windows 11 24H2, our workbench began receiving reports of sudden blue screens, desktop freezes, and game crashes in titles like *ARC Raiders* and *The Finals*.

When we analyzed the crash minidumps in WinDbg, the offending module was identical across all machines:

```text
BugCheck 3B, {c0000005, fffff8038b2410a0, fffff8039210e480, 0}
Probably caused by : inpoutx64.sys ( inpoutx64+10a0 )
IMAGE_NAME: inpoutx64.sys
FAILURE_BUCKET_ID: 0x3B_inpoutx64!unknown_function
```

Here is the exact technical breakdown of why **`KB5121003`** clashes with **`inpoutx64.sys`**, and our step-by-step IT sysadmin runbook to resolve the crashes permanently.

---

## 🔍 The Root Cause: HVCI Kernel Hardening vs. Direct Port I/O

For over a decade, third-party motherboard utilities, RGB lighting controllers, and anti-cheat wrappers relied on a legacy open-source driver called **`inpoutx64.sys`** (*InpOut32 / InpOut64*) to directly read and write to hardware I/O ports without going through standardized Windows Driver Framework (WDF) abstractions.

```
┌────────────────────────────────────────────────────────┐
│  KB5121003 Kernel Memory Isolation Conflict           │
├────────────────────────────────────────────────────────┤
│                                                        │
│  [ Legacy App / Anti-Cheat Wrapper / RGB Tool ]        │
│                         │                              │
│                         ▼ (Direct I/O Port Read/Write) │
│  [ inpoutx64.sys (Legacy Kernel Driver) ]              │
│                         │                              │
│  ❌ [KB5121003 HVCI Block ➔ Crash 0x3B / 0x50]        │
│                         │                              │
│                         ▼                              │
│  [ Windows 11 24H2 Kernel (Paging Protection) ]        │
│                                                        │
└────────────────────────────────────────────────────────┘
```

With update **KB5121003**, Microsoft enforced strict kernel memory paging protections under Hypervisor-Protected Code Integrity (HVCI). When `inpoutx64.sys` attempts an unmapped direct port access, Windows instantly terminates the thread with **`0x3B` (`SYSTEM_SERVICE_EXCEPTION`)** or **`0x50` (`PAGE_FAULT_IN_NONPAGED_AREA`)**.

---

## 🛠️ Step 1: Locate the Application Hosting inpoutx64.sys

Before removing the driver, find which vendor software installed it on your system.

Open **PowerShell as Administrator** and execute:

```powershell
# Query all active kernel drivers for inpoutx64
Get-CimInstance Win32_SystemDriver | Where-Object { 
    $_.PathName -like "*inpoutx64.sys*" -or $_.Name -like "*inpout*" 
} | Select-Object Name, DisplayName, PathName, State
```

Common applications bundling this driver include:
- Legacy motherboard RGB suites (older Asus Aura Sync, Gigabyte RGB Fusion)
- OpenRGB versions released prior to native Windows Dynamic Lighting support
- Outdated peripheral monitoring utilities (NZXT CAM legacy plugins, EVGA Precision X1)
- Custom game launchers and anti-cheat compatibility thunks

---

## 🛠️ Step 2: Unload & Delete the Driver via Service Controller (`sc`)

Because `inpoutx64.sys` is dropped directly into `System32\drivers` as a kernel service rather than a standard PnP INF package, use Windows Service Controller (`sc.exe`) to unload and unregister it:

Run the following commands in an elevated PowerShell or Command Prompt terminal:

```powershell
# 1. Stop the running kernel driver service
sc.exe stop inpoutx64

# 2. Delete the driver service registration from the Service Control Manager
sc.exe delete inpoutx64

# 3. Permanently remove the physical binary from the drivers directory
Remove-Item -Path "$env:SystemRoot\System32\drivers\inpoutx64.sys" -Force -ErrorAction SilentlyContinue
Write-Host "✅ inpoutx64.sys service unregistered and binary removed." -ForegroundColor Green
```

Restart your PC after executing these commands.

---

## 🛠️ Step 3: Switch to Windows 11 Native Dynamic Lighting

If you were using legacy RGB software, update to versions that support Microsoft's native **Windows 11 Dynamic Lighting**:

1. Open **Settings > Personalization > Dynamic Lighting**.
2. Toggle **Use Dynamic Lighting on my devices** to **On**.
3. Modern peripheral suites (including updated OpenRGB and vendor apps) now route lighting commands through standard HID interfaces rather than raw kernel port I/O.

---

## 🛠️ Step 4: Enterprise Rollback (wushowhide & wusa)

If you manage industrial workstations or legacy test benches where proprietary software strictly depends on direct port I/O, you can temporarily roll back **KB5121003** while planning driver migration:

```powershell
# Uninstall KB5121003 silently and prompt for restart
wusa /uninstall /kb:5121003 /quiet /promptrestart
```

To prevent Windows Update from automatically reinstalling the update overnight:
1. Download Microsoft's **Show or Hide Updates** troubleshooter (`wushowhide.diagcab`).
2. Click **Hide updates** and check **KB5121003**.
