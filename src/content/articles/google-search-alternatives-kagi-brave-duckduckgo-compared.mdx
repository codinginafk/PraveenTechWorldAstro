## Search Index Independence: The Syndication Problem

Not all alternative search engines build their own web crawlers. Building and maintaining a multi-billion-page web crawler is technically difficult and capital-intensive. Consequently, most "private" search engines are simply metasearch wrappers purchasing syndicated API feeds from Microsoft Bing or Google.

If an alternative relies 100% on Bing's API, it inherits Bing's crawling delays, content suppression policies, and regional index blind spots.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    SEARCH INDEX INDEPENDENCE SPECTRUM                   │
└─────────────────────────────────────────────────────────────────────────┘

  [ 100% INDEPENDENT ]                               [ 100% SYNDICATED ]
       Googlebot           Bravebot              Kagi             DuckDuckGo
  (Proprietary/Ad)     (>99% Independent)     (Hybrid/Teclis)    (Bing API Feed)
         ▲                    ▲                    ▲                    ▲
         │                    │                    │                    │
  Crawls everything   Crawls 10B+ pages    Proprietary crawler  No own crawler;
  Profiles users.     Zero user profiling. + anonymized APIs.   relies on Bing.
```

### Search Engine Architecture & Governance Matrix

| Search Engine | Primary Crawler / Index | Default Telemetry / Logging | Monetization Model | API Syndication Source |
| :--- | :--- | :--- | :--- | :--- |
| **Google** | 100% Proprietary (Googlebot) | Full Device & Behavioral Fingerprinting | Targeted Advertising Auction | None |
| **Brave Search** | **>99% Independent Index (Bravebot)** | Zero Profiling / Anonymous Queries | Optional Private Ads / Premium | Minimal Bing fallback |
| **Kagi** | **Hybrid (Teclis + Non-Ad APIs)** | Strict Zero-Log Policy | Paid Subscription ($5–$10/mo) | Anonymized Bing/Brave/Mojeek |
| **DuckDuckGo** | Under 15% Independent (DuckDuckBot) | Anonymous Sessions (No Cookies) | Contextual Keyword Ads | Microsoft Bing Syndication |
| **SearXNG** | **0% (Decentralized Metasearch)** | Host-Only (Zero Third-Party) | 100% Free / Open Source | 70+ Configurable Engines |

In our testing, **Brave Search** represents the most significant engineering achievement in consumer search: it is the only Western search engine built from the ground up since the mid-2000s that serves nearly 100% of queries from its own crawler without relying on Google or Microsoft infrastructure.

To verify what happens to your data when you execute a search, our team set up an isolated Debian virtual machine routed through an external gateway running Wireshark. We issued 50 identical search queries across all five platforms and captured outbound DNS queries, TLS handshakes, and third-party tracking calls.

### What the Network Traces Revealed

```

=============================================================================

   - Telemetry Domains: play.google.com/log, doubleclick.net, google-analytics.com

   - Telemetry Payload: Viewport size, client GPU renderer string, precise keystroke timing

2. DuckDuckGo:
   - Outbound HTTP/TLS Connections: 4 endpoints
   - Telemetry Domains: None (Zero tracking cookies)
   - Ad Endpoints: links.duckduckgo.com (contextual affiliate routing)
   - Cookies Transmitted: None

3. Brave Search:
   - Outbound HTTP/TLS Connections: 2 endpoints (search.brave.com, cdn.brave.com)
   - Telemetry Domains: None
   - Cookies Transmitted: None
   - Network Payload: Pure TLS 1.3 encrypted query string

4. Kagi Search:
   - Outbound HTTP/TLS Connections: 1 endpoint (kagi.com)
   - Telemetry Domains: None
   - Cookies Transmitted: 1 single-session session token (kagi_session)
```

If your goal is eliminating behavioral ad-profiling without spending a dollar, **Brave Search** and **DuckDuckGo** cleanly defeat Google. If your goal is zero external data exposure, self-hosting **SearXNG** completely decouples your client machine from public search providers.

## The 50-Query Technical Recall Benchmark

Privacy means little if the search engine returns useless results. Our team constructed a benchmark consisting of **50 difficult engineering queries**, divided into three distinct categories:

1. **Obscure Kernel & Hardware Errors:** Specific stop codes, Linux ACPI kernel panics, and AMD GPU microcode crashes.
2. **Modern Programming Syntax:** C++23 range adapters, Rust borrow-checker edge cases, and Docker rootless daemon socket permissions.
3. **Hardware Workbench Runbooks:** Serial console pinouts, BIOS recovery key combinations, and motherboard VRM component datasheets.

### Benchmark Scoring Results

| Search Engine | Relevant Answer in Top 3 Links | Content Farm Spam in Top 5 Links | Developer Documentation Recall Score (0–100) |
| :--- | :--- | :--- | :--- |

The benchmark revealed that Google's raw indexing power is frequently ruined by commercial SEO content farms. Searching for an obscure error like `splwow64 error 0xc0000142` on Google returned three affiliate driver-updater spam sites before reaching Microsoft's community forums. 

On **Kagi** and **Brave Search**, the top result was the direct GitHub issue thread and Microsoft Learn documentation.

## Deep Dive: Kagi's Domain-Ranking Weapon

For software engineers, Kagi's most powerful feature is not just privacy—it is **custom domain prioritization**.

In modern search, content farms like GeeksforGeeks, W3Schools, and auto-generated scraper blogs flood search results with low-quality, out-of-date tutorials designed to harvest ad impressions. 

Kagi allows you to adjust the ranking weight of any domain across four settings:
- **Boosted (+):** Appears at the very top of your search results.
- **Normal (0):** Default ranking.
- **Lowered (-):** Pushed to the bottom of the page.
- **Blocked (X):** Completely removed from all search queries permanently.

### Our Recommended Engineering Domain Rule Set

In our lab workstation profiles, we applied the following global weights:

```text
====================================================================
KAGI CUSTOM DOMAIN RULES (SYSADMIN & DEVELOPER PROFILE)
====================================================================

[BOOSTED DOMAINS]
+++ kernel.org              (Official Linux Kernel Documentation)
+++ archlinux.org           (ArchWiki & Package Bug Trackers)
+++ developer.mozilla.org   (MDN Web Docs)
+++ learn.microsoft.com     (Official Windows & Azure Technical Docs)
+++ github.com              (Direct Repositories & Issue Trackers)
+++ stackoverflow.com       (Community Q&A)

[BLOCKED DOMAINS (PERMANENTLY PURGED)]
XXX w3schools.com           (Superseded by MDN)
XXX geeksforgeeks.org       (Scraped, repetitive SEO articles)
XXX driverguide.com         (Malware-adjacent driver downloaders)
XXX softonic.com            (Bundled adware installers)
XXX howtogeek.com           (Generic consumer fluff)
====================================================================
```

Once these domain rules were active, our team's search speed increased dramatically. A query for `wsl2 nat networking configuration` immediately returned direct Microsoft Learn documentation and GitHub discussion threads, with zero commercial SEO filler.

## Production Runbook: Self-Hosted SearXNG with Docker Compose

If you refuse to trust any external provider with your search queries, **SearXNG** is the ultimate self-hosted solution. When deployed on a home server, VPS, or Raspberry Pi, your local SearXNG instance queries upstream engines on your behalf, strips all user-agent headers, and aggregates the results into a clean, ad-free interface.

### Step 1: Create the Project Directory Structure

Log into your homelab server and create the deployment directory:

```bash
mkdir -p ~/searxng && cd ~/searxng
mkdir -p searxng
```

### Step 2: Configure docker-compose.yml

Create a `docker-compose.yml` file configuring the SearXNG container and an isolated Redis cache:

```yaml
version: '3.8'

services:
  redis:
    image: redis:7-alpine
    container_name: searxng-redis
    command: redis-server --save "" --appendonly no
    restart: unless-stopped
    networks:
      - searxng-network
    tmpfs:
      - /var/run/redis:rw,size=64M,uid=999,gid=999

  searxng:
    image: searxng/searxng:latest
    container_name: searxng-app
    restart: unless-stopped
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - ./searxng:/etc/searxng:rw
    environment:
      - SEARXNG_BASE_URL=http://127.0.0.1:8080/
    networks:
      - searxng-network
    depends_on:
      - redis

networks:
  searxng-network:
    driver: bridge
```

### Step 3: Generate Secret Key and Configure settings.yml

Generate a cryptographically random secret key and create `searxng/settings.yml`:

```bash
# Generate random 32-byte secret key
openssl rand -hex 32
```

Now create `searxng/settings.yml` and paste the following production configuration:

```yaml
use_default_settings: true

general:
  debug: false
  instance_name: "Lab SearXNG Search"

search:
  safe_search: 0
  autocomplete: "duckduckgo"
  default_lang: "en"
  formats:
    - html
    - json

server:
  # Replace with the output of 'openssl rand -hex 32'
  secret_key: "PASTE_YOUR_GENERATED_SECRET_KEY_HERE"
  limiter: false
  image_proxy: true
  method: "GET"

redis:
  url: redis://redis:6379/0

engines:
  - name: google
    engine: google
    use_mobile_ui: false
    disabled: false
  - name: brave
    engine: brave
    disabled: false
  - name: duckduckgo
    engine: duckduckgo
    disabled: false
  - name: bing
    engine: bing
    disabled: false
  - name: github
    engine: github
    disabled: false
  - name: archwiki
    engine: archlinux
    disabled: false
```

### Step 4: Start the Service and Verify

Launch the container stack in detached mode:

```bash
docker compose up -d
```

Verify that both containers are healthy:

```bash
docker compose ps
curl -I http://127.0.0.1:8080
```

You can now access your private search engine at `http://localhost:8080` or expose it securely behind an Nginx reverse proxy with HTTPS.

## Browser Integration & Default Search Configuration

To make your new search engine frictionless, set it as your browser's default omnibox search handler.

### Setting Brave Search as Default
1. Navigate to **Settings > Search engine**.
2. Under "Search engine used in the address bar", select **Brave Search**.
3. URL String: `https://search.brave.com/search?q=%s`

### Setting Kagi as Default
1. Open Kagi Settings and copy your private session token URL.
2. In your browser's search engine settings, add a new search provider:
   - **Name:** Kagi
   - **Shortcut:** `@k`
   - **URL with %s in place of query:** `https://kagi.com/search?q=%s`

### Adding Self-Hosted SearXNG
1. Open your self-hosted SearXNG URL in Chrome or Firefox.
2. In the browser address bar, click the search icon or open Search Settings.
3. Add search engine:
   - **URL:** `http://localhost:8080/search?q=%s`
