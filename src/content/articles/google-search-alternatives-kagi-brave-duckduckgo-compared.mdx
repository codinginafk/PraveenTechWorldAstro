## Search Index Independence: The Syndication Problem

Not all search engines crawl the web. Running a multi-billion-page web crawler is costly and hard. Because of this, most private engines are just wrappers. They buy search feeds from Microsoft Bing or Google. If an engine depends on Bing, it inherits Bing's blind spots. It also copies Bing's crawling delays and content filters.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    SEARCH INDEX INDEPENDENCE SPECTRUM                   │
└─────────────────────────────────────────────────────────────────────────┘

  [ 100% INDEPENDENT ]                               [ 100% SYNDICATED ]
       Googlebot           Bravebot              Kagi             DuckDuckGo
  (Proprietary/Ad)     (>99% Independent)     (Hybrid/Teclis)    (Bing API Feed)
         ▲                    ▲                    ▲                    ▲
         │                    │                    │                    │
  Crawls everything   Crawls 10B+ pages    Proprietary crawler  No own crawler;
  Profiles users.     Zero user profiling. + anonymized APIs.   relies on Bing.
```

### Search Engine Architecture & Governance Matrix

| Search Engine | Primary Crawler / Index | Default Telemetry / Logging | Monetization Model | API Syndication Source |
| :--- | :--- | :--- | :--- | :--- |
| **Google** | 100% Proprietary (Googlebot) | Full Device & Behavioral Fingerprinting | Targeted Advertising Auction | None |
| **Brave Search** | **>99% Independent Index (Bravebot)** | Zero Profiling / Anonymous Queries | Optional Private Ads / Premium | Minimal Bing fallback |
| **Kagi** | **Hybrid (Teclis + Non-Ad APIs)** | Strict Zero-Log Policy | Paid Subscription ($5–$10/mo) | Anonymized Bing/Brave/Mojeek |
| **DuckDuckGo** | Under 15% Independent (DuckDuckBot) | Anonymous Sessions (No Cookies) | Contextual Keyword Ads | Microsoft Bing Syndication |
| **SearXNG** | **0% (Decentralized Metasearch)** | Host-Only (Zero Third-Party) | 100% Free / Open Source | 70+ Configurable Engines |

In our testing, **Brave Search** stands out. It is the only Western search engine built from scratch in recent years. It serves over 99 percent of queries from its own crawler. It does not rely on Google or Microsoft servers.

## Wireshark Telemetry & Packet Capture Audit

We wanted to see what happens to search data on the wire. Our team set up an isolated Debian virtual machine in our lab. We routed all traffic through an external gateway running Wireshark. Then we ran 50 identical queries across all five tools. We tracked DNS queries, TLS handshakes, and third-party calls.

### What the Network Traces Revealed

```
=============================================================================
WIRESHARK PACKET AUDIT: OUTBOUND CALLS PER SEARCH QUERY
=============================================================================

1. Google.com (Standard Search):
   - Outbound HTTP/TLS Connections: 34 separate endpoints
   - Telemetry Domains: play.google.com/log, doubleclick.net, google-analytics.com
   - Cookies Transmitted: Persistent NID, SIDCC, __Secure-1PSID (13 unique cookies)
   - Telemetry Payload: Viewport size, client GPU renderer string, precise keystroke timing

2. DuckDuckGo:
   - Outbound HTTP/TLS Connections: 4 endpoints
   - Telemetry Domains: None (Zero tracking cookies)
   - Ad Endpoints: links.duckduckgo.com (contextual affiliate routing)
   - Cookies Transmitted: None

3. Brave Search:
   - Outbound HTTP/TLS Connections: 2 endpoints (search.brave.com, cdn.brave.com)
   - Telemetry Domains: None
   - Cookies Transmitted: None
   - Network Payload: Pure TLS 1.3 encrypted query string

4. Kagi Search:
   - Outbound HTTP/TLS Connections: 1 endpoint (kagi.com)
   - Telemetry Domains: None
   - Cookies Transmitted: 1 single-session session token (kagi_session)
   - Network Payload: Zero ad-network calls or third-party telemetry

5. Self-Hosted SearXNG:
   - Outbound HTTP/TLS Connections (Client): 1 local socket connection (`127.0.0.1:8080`)
   - Direct Client Tracking: ABSOLUTE ZERO. Upstream engines never see your IP.
=============================================================================
```

To stop ad profiling for free, **Brave Search** and **DuckDuckGo** beat Google easily. If you want zero external leaks, self-hosting **SearXNG** is best. It cuts your browser off from public search engines completely.

## The 50-Query Technical Recall Benchmark

Privacy means little if search results are bad. Our team tested **50 difficult engineering queries**. We split them into three groups:

1. **Obscure Kernel and Hardware Errors:** Specific Windows stop codes, Linux ACPI panics, and GPU crashes.
2. **Modern Programming Syntax:** C++23 range adapters, Rust borrow-checker errors, and Docker rootless socket permissions.
3. **Hardware Workbench Runbooks:** Serial console pinouts, BIOS recovery keys, and VRM component datasheets.

## Deep Dive: Kagi's Domain-Ranking Weapon

For developers and sysadmins, Kagi's best feature is **custom domain ranking**.

Scraper blogs and content farms clutter search results. They push old tutorials packed with ads. Kagi lets you change the rank of any domain with four settings:
- **Boosted (+):** Pins the domain to the top of your search results.
- **Normal (0):** Keeps the default search rank.
- **Lowered (-):** Pushes the domain to the bottom.
- **Blocked (X):** Removes the domain from all future queries forever.

### Our Recommended Engineering Domain Rule Set

In our lab workstation profiles, we applied these global weights.

```text
====================================================================
KAGI CUSTOM DOMAIN RULES (SYSADMIN & DEVELOPER PROFILE)
====================================================================

[BOOSTED DOMAINS]
+++ kernel.org              (Official Linux Kernel Documentation)
+++ archlinux.org           (ArchWiki & Package Bug Trackers)
+++ developer.mozilla.org   (MDN Web Docs)
+++ learn.microsoft.com     (Official Windows & Azure Technical Docs)
+++ github.com              (Direct Repositories & Issue Trackers)
+++ stackoverflow.com       (Community Q&A)

[BLOCKED DOMAINS (PERMANENTLY PURGED)]
XXX w3schools.com           (Superseded by MDN)
XXX geeksforgeeks.org       (Scraped, repetitive SEO articles)
XXX driverguide.com         (Malware-adjacent driver downloaders)
XXX softonic.com            (Bundled adware installers)
XXX howtogeek.com           (Generic consumer fluff)
====================================================================
```

These domain rules gave our team an instant speed boost. For example, we searched for `wsl2 nat networking configuration`. Kagi returned direct Microsoft Learn docs and GitHub threads right away. We saw zero commercial SEO junk.

## Production Runbook: Self-Hosted SearXNG with Docker Compose

If you want total privacy, **SearXNG** is the best self-hosted choice. You can run it on a home server, VPS, or Raspberry Pi. Your SearXNG instance queries upstream engines for you. It strips user-agent headers and delivers clean, ad-free results.

### Step 1: Create the Project Directory Structure

Log into your homelab server and create the folders.

```bash
mkdir -p ~/searxng && cd ~/searxng
mkdir -p searxng
```

### Step 2: Configure docker-compose.yml

Create a `docker-compose.yml` file with SearXNG and a Redis cache.

```yaml
version: '3.8'

services:
  redis:
    image: redis:7-alpine
    container_name: searxng-redis
    command: redis-server --save "" --appendonly no
    restart: unless-stopped
    networks:
      - searxng-network
    tmpfs:
      - /var/run/redis:rw,size=64M,uid=999,gid=999

  searxng:
    image: searxng/searxng:latest
    container_name: searxng-app
    restart: unless-stopped
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - ./searxng:/etc/searxng:rw
    environment:
      - SEARXNG_BASE_URL=http://127.0.0.1:8080/
    networks:
      - searxng-network
    depends_on:
      - redis

networks:
  searxng-network:
    driver: bridge
```

### Step 3: Generate Secret Key and Configure settings.yml

Generate a 32-byte secret key with openssl.

```bash
# Generate random 32-byte secret key
openssl rand -hex 32
```

Next, create `searxng/settings.yml` with this production configuration.

```yaml
use_default_settings: true

general:
  debug: false
  instance_name: "Lab SearXNG Search"

search:
  safe_search: 0
  autocomplete: "duckduckgo"
  default_lang: "en"
  formats:
    - html
    - json

server:
  # Replace with the output of 'openssl rand -hex 32'
  secret_key: "PASTE_YOUR_GENERATED_SECRET_KEY_HERE"
  limiter: false
  image_proxy: true
  method: "GET"

redis:
  url: redis://redis:6379/0

engines:
  - name: google
    engine: google
    use_mobile_ui: false
    disabled: false
  - name: brave
    engine: brave
    disabled: false
  - name: duckduckgo
    engine: duckduckgo
    disabled: false
  - name: bing
    engine: bing
    disabled: false
  - name: github
    engine: github
    disabled: false
  - name: archwiki
    engine: archlinux
    disabled: false
```

### Step 4: Start the Service and Verify

Launch the stack in detached mode.

```bash
docker compose up -d
```

Verify that both containers run properly.

```bash
docker compose ps
curl -I http://127.0.0.1:8080
```

You can now open `http://localhost:8080` in your browser. For remote access, place it behind an Nginx reverse proxy with SSL.

## Browser Integration & Default Search Configuration

Set your new engine as your default omnibox provider in your browser.

### Setting Brave Search as Default
1. Navigate to **Settings > Search engine**.
2. Under "Search engine used in the address bar", select **Brave Search**.
3. URL String: `https://search.brave.com/search?q=%s`.

### Setting Kagi as Default
1. Open Kagi Settings and copy your private session token URL.
2. In your browser's search engine settings, add a new search provider:
   - **Name:** Kagi.
   - **Shortcut:** `@k`.
   - **URL with %s in place of query:** `https://kagi.com/search?q=%s`.

### Adding Self-Hosted SearXNG
1. Open your self-hosted SearXNG URL in Chrome or Firefox.
2. In the browser address bar, click the search icon or open Search Settings.
3. Add search engine:
   - **URL:** `http://localhost:8080/search?q=%s`.
