During an active server outage or workstation crash, opening the Windows **Event Viewer (`eventvwr.msc`)** is often an exercise in frustration. Between thousands of benign `Information` messages, cryptically formatted `Event ID` numbers, and nested XML blobs, isolating the single failing driver or crashed service wastes critical minutes.

On our IT workbench, our team engineered an automated solution: **a lightweight PowerShell tool that extracts critical system anomalies and queries an on-premise DeepSeek R1 reasoning model via Ollama for instant root-cause analysis**.

Because the AI runs entirely locally via Ollama, **zero corporate log data, internal IP addresses, or Active Directory usernames ever leave your network**.

Here is our production-ready script, prompt configuration, and failure safeguards.

---

## 📊 System Architecture: On-Premise Event Triage

```text
[ Windows Event Logs (.evtx) ]
              │
              ▼ (Hashtable Filter: Level 1,2 Critical/Error)
[ PowerShell Sanitizer: Get-WinEvent ]
              │
              ▼ (REST JSON Payload: http://localhost:11434/api/generate)
[ Local Ollama: DeepSeek-R1:8b (On-Premises VRAM) ]
              │
              ▼

```

## ⚡ Production PowerShell Triage Script (`Invoke-EventTriage.ps1`)

Save this script on your Windows workstation or server:

```powershell
<#
.SYNOPSIS
    Automated Windows Event Log Triage via Local DeepSeek-R1
.DESCRIPTION
    Extracts Critical & Error events from System/Application logs and queries local Ollama.
#>
param (
    [int]$HoursAgo = 3,
    [string]$LogName = "System",
    [string]$OllamaModel = "deepseek-r1:8b",
    [string]$OllamaUrl = "http://localhost:11434/api/generate"
)

$StartTime = (Get-Date).AddHours(-$HoursAgo)
Write-Host "🔍 Extracting Critical & Error events from $LogName since $StartTime..." -ForegroundColor Cyan

# 1. High-Performance Hashtable Event Query
$Events = Get-WinEvent -FilterHashtable @{
    LogName   = $LogName
    Level     = 1, 2 # 1=Critical, 2=Error
    StartTime = $StartTime
} -ErrorAction SilentlyContinue | Select-Object -First 15 TimeCreated, Id, ProviderName, Message

if (-not $Events) {
    Write-Host "✅ No critical or error events found in the last $HoursAgo hours!" -ForegroundColor Green
    exit 0
}

# 2. Format Sanitized Event Table
$LogSummary = ($Events | Format-Table TimeCreated, Id, ProviderName, Message -AutoSize | Out-String).Trim()

# 3. Construct System Prompt with Guardrails
$Prompt = @"
You are an expert Windows Systems Administrator and Incident Response Engineer.
Analyze the following Windows Event Log entries and provide:
1. Root Cause Summary (1-2 sentences)
2. Affected Components & Drivers
3. Exact PowerShell Remediation Commands (Use only official built-in Microsoft cmdlets)

LOG ENTRIES:
$LogSummary
"@

# 4. Dispatch Request to Local Ollama Node
$Payload = @{
    model  = $OllamaModel
    prompt = $Prompt
    stream = $false
} | ConvertTo-Json

Write-Host "🧠 Dispatching logs to local $OllamaModel for reasoning..." -ForegroundColor Yellow

try {
    $Response = Invoke-RestMethod -Uri $OllamaUrl -Method Post -Body $Payload -ContentType "application/json" -TimeoutSec 45
    Write-Host "`n=======================================================" -ForegroundColor DarkGray
    Write-Host "📋 DEEPSEEK INCIDENT TRIAGE REPORT" -ForegroundColor Green
    Write-Host "=======================================================" -ForegroundColor DarkGray
    Write-Host $Response.response
} catch {
    Write-Host "❌ Error communicating with Ollama API at $OllamaUrl. Is Ollama running?" -ForegroundColor Red
}
```

## 🛠️ Lessons Learned & AI Guardrails

When we first tested the prototype against production logs, we isolated two critical failure modes:

### 1. Hallucinated PowerShell Cmdlets
When triaging an `nvlddmkm.sys` display crash, DeepSeek initially recommended running `Restart-NvidiaDisplayService`. That cmdlet does not exist in native Windows PowerShell!
- **Workbench Fix:** We added strict prompt constraints: *"Only recommend official built-in Microsoft cmdlets (e.g., Get-Service, Restart-Service, DISM, sfc, netsh). Never invent custom third-party module cmdlets."*

### 2. Context Window Truncation
Sending 500 un-filtered event logs flooded Ollama's default context buffer, leading to random truncations.
- **Workbench Fix:** We capped extraction to the **15 most recent Critical/Error events** (`-First 15`) and excluded verbose XML schemas.
