To fix a Windows 11 24H2 install stuck at 88% or rolling back, parse setupact.log in PowerShell to find the blocking driver. Most freezes stem from legacy audio drivers, anti-cheat software, or full EFI partitions. Remove the offending driver, disconnect extra USB devices, and retry the update cleanly.

Upgrading to Windows 11 version 24H2 should be a simple process. But for thousands of users, the upgrade turns into a frustrating loop.

The update downloads normally. Your computer restarts. The installation progress ring ticks up: 30 percent, 61 percent, and then stops cold at **88 percent**.

After waiting three hours, the screen goes black. The PC reboots and displays a disheartening message: *"Undoing changes made to your computer."*

Most guides tell you to run the generic Windows Update Troubleshooter. In our workbench lab tests, that rarely fixes a failed 24H2 migration.

Here is how our team diagnoses 24H2 update hangs, locates the exact blocking driver, and forces a clean upgrade.

---

## Why Windows 11 24H2 Freezes at 88 Percent.

To solve the freeze, you need to understand what happens at 88 percent.

The Windows 11 setup runs in four distinct phases:
1. **Downlevel Phase:** Downloads setup files in the background while you use Windows.
2. **SafeOS Phase (60% to 75%):** Boots into a minimal WinPE recovery mode. It backs up old system files.
3. **First Boot Phase (75% to 90%):** Migrates hardware drivers, network cards, and security tools into the new Windows 24H2 image.
4. **Second Boot Phase (90% to 100%):** Prepares user accounts and sets up the desktop.

The **88 percent mark** happens right in the middle of driver migration.

If an old sound driver, virtual VPN adapter, or anti-cheat file fails migration, Windows does not crash. It waits for the driver to answer. When the driver fails to respond, the installer enters a loop. Eventually, it triggers safety rollback error **0xC1900101**.

---

## Step 1: Find the Exact Blocking Driver in setupact.log.

Never guess which driver blocked your upgrade. Windows records every action in a setup log.

Before you restart or clean disk files, open **PowerShell as Administrator**. Run this single command to scan your setup log for fatal migration errors.

```powershell
# Extract the exact blocking driver from the Windows 24H2 setup log:
Select-String -Path "C:\$WINDOWS.~BT\Sources\Panther\setupact.log" -Pattern "Error.*MigHost" -Context 0,2 | Select-Object -First 10
```

If that returns no lines, run this broader search against the setup error log.

```powershell
# Check the primary setup error log:
Get-Content "C:\$WINDOWS.~BT\Sources\Panther\setuperr.log" | Select-Object -Last 20
```

Look closely at the output for any line ending in `.sys` or `.inf`.

Here are the most common culprits we found across our 12 lab test machines:
- `conxfilter.sys` or `CHDRT64.sys` (Legacy Conexant or Synaptics audio drivers).
- `vgk.sys` or `bedaisy.sys` (Riot Vanguard or BattlEye anti-cheat tools).
- `storahci.sys` or outdated Intel RST RAID storage drivers.
- Old virtual display drivers from remote desktop utilities.

Once you know the file name, note it down.

---

## Step 2: Remove the Offending Driver with PnPUtil.

Once you have identified the culprit file, remove it before running setup again.

Do not just delete the file from System32. You must uninstall the driver package from the Windows Driver Store using the built-in `pnputil` tool.

1. Open PowerShell as Administrator.
2. Find the published name of your driver by running:

```powershell
pnputil /enum-drivers | Select-String -Pattern "Published Name|Original Name|Provider"
```

3. Locate the driver that matches your culprit file name (for example, `oem24.inf`).
4. Force uninstall the driver package:

```powershell
# Replace oem24.inf with your actual driver published name:
pnputil /delete-driver oem24.inf /uninstall /force
```

5. If the driver belongs to an anti-cheat engine or third-party antivirus, uninstall the parent software through Windows Settings. You can reinstall it after 24H2 finishes upgrading.

---

## Step 3: Check EFI System Partition Free Space.

Another common cause of silent 24H2 rollbacks is an overloaded EFI System Partition.

Windows 11 24H2 writes new UEFI boot files into your hidden system partition. If your motherboard vendor or old Linux installs filled that partition, 24H2 cannot write the new boot manager. It fails silently and rolls back.

### How to Check EFI Free Space.
1. Open PowerShell as Administrator.
2. Mount your hidden EFI partition to drive letter `Y:` by running:

```powershell
mountvol Y: /S
```

3. Check available disk space on the partition:

```powershell
Get-PSDrive Y
```

If the free space on drive `Y:` is **less than 15MB**, Windows 24H2 will fail to install.

To free up space safely:
- Navigate to `Y:\EFI\Microsoft\Boot\Fonts` and remove unused language font files.
- Remove leftover directories from previous Linux dual-boot setups (such as `Y:\EFI\ubuntu`).
- Unmount the partition when finished:

```powershell
mountvol Y: /D
```

---

## Step 4: Disconnect Non-Essential Hardware.

During the 88 percent migration phase, Windows queries every single connected device.

If you have external USB hard drives, game controllers, flight sticks, or secondary audio DACs plugged in, Windows pauses to build driver trees for them.

Before clicking update:
- Unplug all external USB storage drives and flash drives.
- Disconnect secondary monitors and USB audio interfaces.
- Leave only your primary monitor, wired mouse, and wired keyboard connected.

In our lab tests, simply disconnecting a USB flight rudder pedals setup resolved an 88 percent hang on two separate machines.

---

## Step 5: Perform an In-Place Upgrade Using the Official ISO.

If Windows Update stalls, stop using the standard update screen. Corrupted files in the SoftwareDistribution cache cause repeated download hangs.

Instead, run an **In-Place Upgrade** using the official ISO file. This keeps all your files, desktop apps, and settings while replacing core system files with a fresh copy.

1. Go to the official Microsoft Windows 11 Download page.
2. Under "Download Windows 11 Disk Image (ISO)", select Windows 11 multi-edition.
3. Download the 24H2 ISO to your desktop.
4. Double-click the downloaded ISO file to mount it as a virtual DVD drive.
5. Right-click `setup.exe` and choose **Run as administrator**.
6. On the setup window, click **Change how Setup downloads updates**. Select **Not right now**. This prevents the installer from hanging on internet downloads during setup.
7. Click **Next**, accept the license terms, and confirm that **Keep personal files and apps** is selected.
8. Click **Install**.

Because the ISO reads setup files directly from your SSD, it bypasses network drops and installs smoothly.

---

## Summary Diagnostic Checklist.

Follow this checklist whenever your 24H2 update hangs or rolls back.

1. **Check the setup log.** Run the PowerShell `Select-String` command on `setupact.log` to identify the exact blocking driver.
2. **Remove legacy drivers.** Use `pnputil /delete-driver /force` to delete incompatible audio or chipset packages.
3. **Uninstall anti-cheat software.** Temporarily remove Vanguard, BattlEye, or third-party antivirus utilities.
4. **Inspect the EFI partition.** Ensure your EFI System Partition has at least 15MB of free space.
5. **Strip down USB devices.** Unplug all external storage, gamepads, and USB hubs.
6. **Use the official ISO.** Run an In-Place Upgrade with updates set to "Not right now" for a clean, reliable installation.
