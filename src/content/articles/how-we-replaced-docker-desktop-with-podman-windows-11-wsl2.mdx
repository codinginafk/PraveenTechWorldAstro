> **Direct Answer (How to Replace Docker Desktop with Podman on Windows 11):** To migrate from Docker Desktop to Podman on Windows 11: (1) Ensure WSL2 is updated via `wsl --update`, (2) install Podman using `winget install -e --id RedHat.Podman`, (3) initialize the rootless container engine with `podman machine init --cpus 4 --memory 4096 --disk-size 50` and start it via `podman machine start`, (4) create a global CLI alias (`Set-Alias -Name docker -Value podman`), and (5) configure VS Code Dev Containers to use `podman` as the runtime binary.

## 🔍 1. Architecture: Docker Desktop vs Podman on WSL2

**Direct Answer:** Docker Desktop relies on a centralized background daemon running as root, whereas Podman uses a daemonless fork-exec model where containers run as standard user processes inside WSL2.

To understand why Podman is lighter and more secure, examine the architecture comparison:

```text
# diagrams/docker_vs_podman_architecture.txt
┌────────────────────────────────────────────────────────┐
│     Docker Desktop Architecture (Daemon Model)         │
│                                                        │
│  [ CLI ] ──REST API──▶ [ dockerd (Root Daemon) ]       │
│                                │                       │
│                                ▼                       │
│                        [ Container 1 ] [ Container 2 ] │
│                        (Runs as root inside VM)        │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│       Podman Architecture (Daemonless Model)           │
│                                                        │
│  [ CLI ] ──Fork/Exec──▶ [ conmon ] ──▶ [ Container 1 ] │
│                                                        │
│  [ CLI ] ──Fork/Exec──▶ [ conmon ] ──▶ [ Container 2 ] │
│  (Rootless user process; no centralized crash point)   │
└────────────────────────────────────────────────────────┘
```

Because Podman does not rely on a monolithic background daemon (`dockerd`), a crashed container process never takes down your other development containers. Furthermore, rootless execution maps container UIDs directly to your Windows host user, preventing file permission lockouts.

## ⚙️ 3. Prerequisites Before You Begin

**Direct Answer:** Ensure Windows 11 has the modern WSL2 kernel installed and updated to version 2.3.0 or higher.

Open **PowerShell as Administrator** and verify your WSL2 subsystem:

```powershell
# scripts/verify_wsl_status.ps1
# Check WSL kernel status and update to the latest release
wsl.exe --update
wsl.exe --version
```

If WSL2 is not enabled, install it with `wsl.exe --install --no-distribution` and reboot your workstation.

## 💻 4. Automated PowerShell Podman Installation Script

**Direct Answer:** Run our automated PowerShell setup script (`# scripts/Install-PodmanWSL2.ps1`) to install Podman, provision the WSL2 machine, and establish global CLI aliases.

Execute this script in an administrative PowerShell terminal:

```powershell
# scripts/Install-PodmanWSL2.ps1
<#
.SYNOPSIS
  Installs Podman on Windows 11, configures the WSL2 VM, and creates docker aliases.
.EXAMPLE
  .\Install-PodmanWSL2.ps1
#>
$ErrorActionPreference = "Stop"

Write-Host "📦 Step 1: Installing Podman via WinGet..." -ForegroundColor Cyan
winget install -e --id RedHat.Podman --accept-package-agreements --accept-source-agreements

Write-Host "⚙️ Step 2: Initializing Podman WSL2 Machine..." -ForegroundColor Cyan
# Allocate 4 vCPUs, 4GB RAM, and 50GB dynamically expanding disk
podman machine init --cpus 4 --memory 4096 --disk-size 50

Write-Host "🚀 Step 3: Starting Podman Machine..." -ForegroundColor Cyan
podman machine start

Write-Host "🔗 Step 4: Configuring Global Docker Alias..." -ForegroundColor Cyan
$ProfilePath = $PROFILE
if (-not (Test-Path $ProfilePath)) {
    New-Item -Path $ProfilePath -ItemType File -Force | Out-Null
}
Add-Content -Path $ProfilePath -Value "`nSet-Alias -Name docker -Value podman"
Write-Host "  Added 'Set-Alias -Name docker -Value podman' to $ProfilePath" -ForegroundColor Green

Write-Host "✅ Verifying Podman Container Engine..." -ForegroundColor Cyan
podman run --rm hello-world
Write-Host "🎉 Podman is fully installed and operational on Windows 11!" -ForegroundColor Green
```

## 🔄 5. Migrating Docker Compose Workflows

**Direct Answer:** Run your existing `docker-compose.yml` files directly using native `podman compose` without changing service definitions.

Podman 4.x and 5.x include built-in compose translation. Inside PowerShell or your WSL2 terminal:

```bash
# scripts/run_podman_compose.sh
# Check native compose version
podman compose version

# Launch your multi-container stack in detached mode
podman compose up -d

# Inspect live container logs
podman compose logs -f

# Teardown stack and networks
podman compose down
```

### Addressing Volume Permission Errors (`:Z` Flag):
Because rootless Podman strictly isolates container namespaces, host bind mounts may encounter permission denied errors. To resolve this, append the `:Z` SELinux relabeling flag to your volumes:

```yaml
# configs/docker-compose.yml
services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html:Z  # :Z applies private unshared label
```

## 🛠️ 6. Configuring VS Code Dev Containers with Podman

**Direct Answer:** Configure the Visual Studio Code Dev Containers extension to use Podman by setting `dockerPath` in your user settings.

1. In VS Code, press `Ctrl + Shift + P` and select **Preferences: Open User Settings (JSON)**.
2. Add the following keys to point container orchestration to the Podman executable:

```json
// configs/vscode_settings.json
{
  "dev.containers.dockerPath": "podman",
  "docker.dockerPath": "podman"
}
```

3. Restart VS Code. When opening a repository containing a `.devcontainer` folder, select **Reopen in Container**. VS Code will build and spawn your environment via Podman seamlessly.

## 🧹 7. Cleanly Uninstalling Docker Desktop

**Direct Answer:** Completely purge Docker Desktop and its orphaned WSL2 storage volumes to reclaim 20GB+ of SSD space and prevent networking conflicts.

Once you have verified Podman operates properly, purge Docker Desktop from Windows:

```powershell
# scripts/uninstall_docker_desktop.ps1
# Uninstall Docker Desktop binary
winget uninstall Docker.DockerDesktop

# Unregister orphaned Docker WSL2 storage distributions
wsl --unregister docker-desktop
wsl --unregister docker-desktop-data

# Purge leftover local application caches
Remove-Item -Recurse -Force "$env:APPDATA\Docker" -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\Docker" -ErrorAction SilentlyContinue
Write-Host "✅ Docker Desktop completely uninstalled and storage reclaimed!" -ForegroundColor Green
```
