Google Photos is one of Google's stickiest consumer products because of automated facial tagging, semantic visual search, and seamless mobile background backups. However, it also feeds Google's multi-modal AI models with personal family albums, geolocation metadata, and biometric facial vectors.

We migrated an 80,000-photo archive from Google Takeout to evaluate two premier private alternatives: Immich (self-hosted) and Ente Photos (cloud end-to-end encrypted).

## Feature and Privacy Comparison

| Feature | Google Photos | Immich (Self-Hosted) | Ente Photos (E2EE Cloud) |
| :--- | :--- | :--- | :--- |
| **Hosting Model** | Google Cloud Servers | Homelab / Docker / TrueNAS | Encrypted Distributed Cloud |
| **Encryption Standard** | Server-Side (Google Scans Content) | Local Disk Encryption (LUKS) | Zero-Knowledge XChaCha20-Poly1305 |
| **Facial Recognition** | Cloud Neural Network | Local Onnx / CUDA ML Microservice | Local On-Device Neural Search |
| **Semantic CLIP Search** | Cloud Multi-Modal AI | Local CLIP Model (CPU/GPU) | Local Embeddings on Device |
| **Mobile Auto-Backup** | Native Android/iOS Integration | Background App Sync with Foreground Catchup | Native Mobile Client with Full E2EE Sync |

## The Google Takeout Metadata Nightmare

The greatest friction when leaving Google Photos is Google Takeout's JSON metadata fragmentation. When you download your archive, Google strips GPS coordinates and modified timestamps out of image files and dumps them into corresponding `.json` sidecar files.

We solved this using `immich-go` with automated metadata remuxing:

```bash
# Automated EXIF Remux and Direct Ingestion into Immich
docker run -v /path/to/takeout:/input -v /path/to/immich:/upload \
  ghcr.io/immich-app/immich-go:latest upload \
  --server http://192.168.1.100:2283/api \
  --key YOUR_IMMICH_API_KEY \
  --import-takeout /input
```
