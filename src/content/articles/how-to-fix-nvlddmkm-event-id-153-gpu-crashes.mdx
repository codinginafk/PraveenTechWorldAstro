If your Windows 11 PC suddenly freezes during heavy 3D rendering, 4K gaming, or local AI inference with Ollama, followed by a momentary black screen and a desktop crash, checking the Windows **Event Viewer (`eventvwr.msc`)** often reveals a string of yellow warning icons:

```text
The description for Event ID 153 from source nvlddmkm cannot be found.
\Device\Video3: The IO operation at logical block address ... was retried.
```bash

Unlike the more common **[Event ID 13 (Shader Timeout)](/blog/how-to-fix-nvlddmkm-sys-event-id-13-gpu-driver-crashes-windows-11)** or **Event ID 14 (Physical VRAM Hardware Fault)**, **Event ID 153 is an I/O paging deadlock**. It occurs when Windows attempts to swap memory pages between physical VRAM and the system pagefile over the PCIe bus, encounters latency, and triggers an I/O retry timeout.

On our hardware workbench, our team spent dozens of hours stress-testing RTX 30, 40, and 50-series rigs to isolate the exact software, registry, and BIOS triggers behind Event ID 153.

Here is our complete, step-by-step diagnostic and repair playbook.

---

## 📊 NVIDIA Event ID Diagnostic Matrix

| Event ID | Event Source | Technical Root Cause | Primary Culprit | Best Fix |
|:---|:---|:---|:---|:---|
| **Event 13** | `nvlddmkm` | Graphics engine shader timeout | Driver execution stall | Increase `TdrDelay` to 8s |
| **Event 14** | `nvlddmkm` | Physical memory parity / bus fault | Unstable VRAM overclock / heat | Remove GPU memory OC |
| **Event 153** | `nvlddmkm` | **I/O paging timeout across PCIe bus** | **HAGS paging conflict / PCIe link drop** | **Disable HAGS & Force PCIe Gen4** |
| **Event 4101** | `Display` | Successful TDR driver recovery | Kernel watchdog caught freeze | Clean DDU driver wipe |

## 🔍 Step 1: Extract Exact Event ID 153 Logs via PowerShell

Before making configuration changes, verify the frequency and exact hardware device index of your driver crashes.

Open **PowerShell as Administrator** and execute:

```powershell
# Query all nvlddmkm Event 153, 13, and 14 crashes from the last 14 days
Get-WinEvent -FilterHashtable @{
    LogName   = 'System'
    ProviderName = 'nvlddmkm'
    Id        = 153, 13, 14
    StartTime = (Get-Date).AddDays(-14)
} -ErrorAction SilentlyContinue | Select-Object TimeCreated, Id, Message | Format-Table -AutoSize
```powershell

If the logs show recurring `Id: 153` entries clustered around memory-intensive tasks, proceed with the fixes below.

---

## ⚡ Step 2: Disable Hardware-Accelerated GPU Scheduling (HAGS)

In Windows 11 24H2, **Hardware-Accelerated GPU Scheduling (HAGS)** offloads high-priority memory scheduling tasks directly to the GPU's dedicated scheduling processor. However, when physical VRAM saturates near 95% capacity, HAGS memory virtualization frequently deadlocks against the Windows kernel memory manager, triggering Event 153.

To disable HAGS:

1. Press **Win + I** to open **Settings**.
2. Navigate to **System $\rightarrow$ Display $\rightarrow$ Graphics $\rightarrow$ Default graphics settings**.
3. Toggle **Hardware-accelerated GPU scheduling** to **Off**.
4. Restart your workstation.

---

## 🛠️ Step 3: Increase Windows TDR Paging Cushion (`TdrDelay` & `TdrDdiDelay`)

By default, the Windows graphics watchdog resets the GPU driver if an I/O paging queue stalls for longer than **2 seconds**. Increasing this timeout threshold allows the graphics card to flush pending I/O packets without crashing.

Execute this script in **PowerShell as Administrator**:

```powershell
# Set TDR Timeout to 8 Seconds (Decimal)
$GraphicsKey = "HKLM:\SYSTEM\CurrentControlSet\Control\GraphicDrivers"

Set-ItemProperty -Path $GraphicsKey -Name "TdrDelay" -Value 8 -Type DWord
Set-ItemProperty -Path $GraphicsKey -Name "TdrDdiDelay" -Value 8 -Type DWord
Set-ItemProperty -Path $GraphicsKey -Name "TdrLevel" -Value 3 -Type DWord

Write-Host "✅ TDR Registry Cushions successfully set to 8 seconds!" -ForegroundColor Green
```

*Restart your PC to commit the new kernel graphics watchdog parameters.*

---

## ⚙️ Step 4: Lock PCIe Link Speed to Gen 4/Gen 3 in Motherboard BIOS

Modern PCIe Gen 5 and Gen 4 motherboards dynamically downshift PCIe lane speeds to save power during idle states. When a heavy 3D load or CUDA model suddenly requests 16GB of memory bandwidth, the microsecond delay in lane clock negotiation causes a bus timeout, logging Event 153.

1. Reboot your PC and press **Del** or **F2** to enter the **BIOS/UEFI**.
2. Navigate to **Advanced $\rightarrow$ PCI Subsystem Settings** (or **System Agent Configuration / PEG Port Configuration**).
3. Change **PCIe x16 Link Speed** from **Auto** to **Gen 4** (or **Gen 3** if using a vertical GPU riser cable).
4. Save changes and exit (**F10**).

---

## 🧹 Step 5: Clean Driver Purge via DDU in Windows Safe Mode

Corrupted DirectX shader caches and residual driver DLLs from previous updates frequently corrupt the paging queue.

1. Download the latest official **NVIDIA WHQL Studio or Game Ready Driver** to your desktop.
2. Download **Display Driver Uninstaller (DDU)** from Wagnardsoft.
3. Disconnect your internet connection (unplug Ethernet / toggle Airplane Mode) to prevent Windows Update from installing a generic driver during reboot.
4. Hold **Shift** while clicking **Restart** in the Start Menu.
5. Select **Troubleshoot $\rightarrow$ Advanced options $\rightarrow$ Startup Settings $\rightarrow$ Restart**, then press **4** for **Safe Mode**.
6. Open DDU, select **GPU $\rightarrow$ NVIDIA**, and click **Clean and restart**.
7. Boot back into Windows, run the NVIDIA installer, choose **Custom (Advanced)**, and check **Perform a clean installation**.

---

## 📋 Summary & Further Reading

`nvlddmkm.sys` Event ID 153 is fundamentally an **I/O paging queue timeout** rather than a dead GPU. By disabling HAGS, extending `TdrDelay` to 8 seconds, locking PCIe link speeds in BIOS, and executing a clean DDU reinstall, you resolve the bus negotiation bottleneck.
