> **Direct Answer (NVIDIA Event ID 153):** The `nvlddmkm Event ID 153` error occurs when the NVIDIA kernel driver retries an IO or paging request to video memory that timed out. The 4 fastest fixes are: (1) perform a clean driver installation with DDU in Safe Mode, (2) temporarily toggle Hardware-Accelerated GPU Scheduling (HAGS) under Windows Graphics Settings, (3) revert custom GPU clock offsets and power limits in MSI Afterburner, and (4) verify clean PCIe seating and dedicated 12VHPWR/PCIe power connectors.

Seeing `nvlddmkm` Event ID 153 in Windows 11 can be alarming, especially when a game freezes, the screen flashes black, or an application closes. **The event ID is a clue, not a diagnosis.** The full event message, the workload that was running, the driver version, and nearby System and Application events are needed to separate a driver problem from a power, temperature, software, or hardware problem.

Microsoft’s [Timeout Detection and Recovery documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/timeout-detection-and-recovery) explains how Windows detects and recovers from a graphics operation that stops responding. That documentation does not establish a universal root cause or a guaranteed fix for every NVIDIA event numbered 153. Start with evidence, then test the least destructive explanation first.

If you want to capture the event, open **Event Viewer (`eventvwr.msc`)** and save the complete entry. Some systems show text like:

```text
The description for Event ID 153 from source nvlddmkm cannot be found.
\Device\Video3: The IO operation at logical block address ... was retried.
```

Unlike the separate **[Event ID 13 guide](/blog/how-to-fix-nvlddmkm-sys-event-id-13-gpu-driver-crashes-windows-11)**, Event ID 153 should not be assigned a root cause from the number alone. If Event Viewer says that the description cannot be found, save the event’s **Provider**, **Event ID**, **Level**, **General** message, and **Details** XML. A missing description can make the event harder to interpret, but it is not by itself proof that the graphics card is failing. Correlate the timestamp with display, WHEA-Logger, Kernel-Power, and application events.

Here is a safe diagnostic workflow that keeps the driver, workload, power, cooling, and hardware checks separate.

## 🔍 Step 1: Capture the event before changing anything

Before making configuration changes, verify the frequency, exact message, and hardware device index of the driver events.

Open **PowerShell as Administrator** and execute:

```powershell
# Capture recent NVIDIA display-driver events for correlation
Get-WinEvent -FilterHashtable @{
    LogName   = 'System'
    ProviderName = 'nvlddmkm'
    StartTime = (Get-Date).AddDays(-14)
} -ErrorAction SilentlyContinue |
    Where-Object Id -in 13, 14, 153 |
    Select-Object TimeCreated, Id, LevelDisplayName, Message |
    Format-List
```

Write down the GPU model, NVIDIA driver version, Windows build, application or game, temperature, clocks, and the exact action that preceded the event. If the screen recovered, note whether it recovered on its own or required a restart. A short evidence record is more useful than applying several registry tweaks at once.

---

## ⚡ Step 2: Check graphics settings as a controlled comparison

**Do not treat Hardware-Accelerated GPU Scheduling (HAGS) as a guaranteed Event ID 153 fix.** If the crash began after a graphics-setting change, compare the previous setting, reboot, and repeat the same workload. Change one setting at a time and restore it if the result does not improve.

To make a reversible HAGS comparison:

1. Press **Win + I** to open **Settings**.
2. Navigate to **System $\rightarrow$ Display $\rightarrow$ Graphics $\rightarrow$ Default graphics settings**.
3. Toggle **Hardware-accelerated GPU scheduling** to **Off**.
4. Restart Windows and reproduce the same workload.

If the event continues, restore the original setting. A passing benchmark after one toggle is a data point, not proof that HAGS was the cause.

---

## 🛠️ Step 3: Leave TDR registry values alone

**Do not edit `TdrDelay`, `TdrDdiDelay`, or `TdrLevel` as the default Event ID 153 fix.** Microsoft’s [TDR registry-key documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/tdr-registry-keys) describes these values for driver development and testing and says end users should not manipulate them.

Increasing a timeout can hide an unstable workload while making recovery slower; it does not repair a driver, power supply, GPU, or PCIe connection. If a GPU vendor or Microsoft support case requests a temporary diagnostic value, record the original state, follow that case-specific instruction, and remove the test value afterward. Do not copy a `TdrDelay=8` command from a forum and present it as a general repair.

---

## ⚙️ Step 4: Check the physical path without forcing PCIe speed

**Do not force PCIe Gen 4 or Gen 3 in BIOS simply because Event ID 153 mentions a video device.** Firmware menus and supported link speeds vary by motherboard, GPU, riser, and laptop design. Update motherboard firmware and check the manufacturer’s support instructions first.

For a supported hardware comparison:

1. Return GPU, CPU, and memory clocks and voltages to stock.
2. Check that every GPU power connector is fully inserted; never mix modular cables from different power supplies.
3. Record GPU temperature, hotspot temperature, fan speed, and board power while reproducing the workload.
4. Look for WHEA-Logger, Kernel-Power, or storage errors at the same timestamp.
5. Change a PCIe link setting only when the motherboard or GPU vendor recommends it for your exact hardware, then record and reverse the test if it does not help.

---

## 🧹 Step 5: Clean the driver only when a normal reinstall fails

Use Display Driver Uninstaller as a second-line cleanup when a normal supported reinstall leaves a suspected driver-stack conflict. DDU cannot repair a weak power supply, damaged VRAM, overheating, a faulty PCIe slot, or an application-specific crash.

1. Download a known-good official **NVIDIA WHQL Studio or Game Ready Driver** to your desktop.
2. Download **Display Driver Uninstaller (DDU)** from [Wagnardsoft](https://www.wagnardsoft.com/).
3. Disconnect your internet connection (unplug Ethernet / toggle Airplane Mode) to prevent Windows Update from installing a generic driver during reboot.
4. Hold **Shift** while clicking **Restart** in the Start Menu.
5. Select **Troubleshoot $\rightarrow$ Advanced options $\rightarrow$ Startup Settings $\rightarrow$ Restart**, then press **4** for **Safe Mode**.
6. Open DDU, select **GPU $\rightarrow$ NVIDIA**, and click **Clean and restart**.
7. Boot back into Windows, run the NVIDIA installer, choose **Custom (Advanced)**, and check **Perform a clean installation**.

## 📋 Summary & Further Reading

`nvlddmkm.sys` Event ID 153 is a clue from the NVIDIA display-driver stack, not a complete diagnosis. Capture the full message, test one supported driver path, return hardware to stock, check power and temperatures, and escalate with evidence when the event persists. HAGS and PCIe changes are optional reversible comparisons; TDR registry edits are not a general fix.
